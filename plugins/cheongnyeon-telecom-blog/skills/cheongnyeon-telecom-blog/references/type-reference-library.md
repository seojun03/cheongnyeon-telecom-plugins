# 유형별 레퍼런스 라이브러리

## 목적

새 원고의 제목과 약속을 먼저 분석하고, 같은 유형에서 가장 가까운 대표글 한 편을 주 마스터로 선택한다. 주 마스터의 말투·후킹 수·블록 순서·정보 공개 순서·반론 전개·마무리 위치와 HTML 꾸미기를 1대1로 재구성하고, 새 제목의 내용과 최신 사실만 치환한다. 주 마스터가 충분하면 다른 원문을 읽지 않으며, 필요한 경우에만 같은 유형의 보조 원문 한 편을 추가해 총 2편을 넘기지 않는다.

## 선택 원칙

1. 제목에서 주 유형과 필요한 답을 판별한다.
2. 아래 목록에서 같은 주 유형의 대표글을 찾는다.
3. 제목의 약속·답 개수·후킹 방식·설득 목적이 가장 가까운 대표글 **한 편을 주 마스터**로 선택한다.
4. 주 마스터 원문을 처음부터 끝까지 읽는다. 주 마스터만으로 답을 회수할 수 있으면 다른 원문은 읽지 않는다. 구조가 모호하거나 사용자가 보강을 명시한 경우에만 같은 유형의 보조 원문 1편을 추가해 **총 2편을 넘기지 않는다**.
5. 마스터의 블록 수, 문단 순서, 문장 역할, 소제목 수, 증거와 CTA 위치, 질문과 단호한 문장의 리듬을 그대로 유지한다.
6. `반박분석 3멘트`, `소비자 마음 2차 후킹`, 별도 마무리, 증거 블록은 마스터에 있을 때만 같은 위치와 문장 수로 사용한다. 마스터에 없으면 다른 글에서 가져와 추가하지 않는다.
7. 레퍼런스의 과거 수치·정책·시점은 그대로 가져오지 않고 `brand_facts.md`와 `temporary_information.md`에서 최신값을 선택한다.
8. 원문의 주제 문장을 붙여 넣지 않고, 각 문장의 역할은 유지한 채 새 제목에 필요한 내용으로 치환한다.
9. HTML에서는 주 마스터의 꾸미기 프로필만 사용한다. 보조 원문이 있어도 색·정렬·표·밑줄·사진·줄바꿈·CTA를 가져오거나 섞지 않으며, 글 구조 마스터와 장식 마스터를 분리하거나 공통 디자인을 덧씌우지 않는다.

## 추가 레퍼런스 대기 유형

다음 유형은 사용자가 대표글을 보내면 별도 항목으로 등록한다.

- 사전예약·신제품·재고형
- FAQ·준비물·위치·사후관리형
- 대표 시작·철학·운영 선택형
- 고객 후기·방문 이유형
- 기종별 구매·출시 정보형

한 유형에 대표글을 여러 편 저장할 수는 있다. 그러나 새 원고 한 편을 만들 때는 제목과 가장 가까운 주 마스터 1편을 먼저 선택한다. 보조가 필요할 때만 같은 유형의 원문 1편을 추가해 최대 2편으로 제한하며, 저장된 글이 여러 편이라는 이유로 구조나 말투를 평균 내지 않는다.

## 새 레퍼런스 등록 절차

사용자가 글을 붙여 넣으면 다음 순서로 처리한다.

1. 프로필, 작성일 UI, `이 포스트로 클립 만들기`, `URL 복사`, `통계`, `본문 기타 기능` 등 네이버 화면 문구를 제거한다.
2. 제목, 실제 본문, 사진 캡션 역할, 표·인용 위치만 남긴다.
3. 사용자가 번호나 유형명을 붙였다면 우선 사용하고, 제목 약속과 본문 답이 다를 때만 충돌을 알린다.
4. 제목 약속, 전체 블록 수, 문단 순서, 문장별 역할, 첫 후킹, 2차 후킹 유무, 본문 공개 순서, 반론 전환, 증거 위치, 마무리 위치를 추출한다.
5. 숫자·정책·혜택은 사실 레코드에 등록하고 같은 항목의 최신 게시물 값을 현재값으로 둔다.
6. 레퍼런스 ID와 원문 링크를 이 문서에 추가한다.
7. 같은 유형의 기존 대표글과 강점이 완전히 겹치면 새 글을 추가하지 않고 기존 프로필의 관찰만 보강한다.

## 새 글 생성 절차

1. `topic-idea-library.json`에서 선택한 `ideaType`과 제목의 문자를 함께 읽고 `설명·가격 비교 | 경고·피해예방 | 가격·권위 | 사전예약·재고 | FAQ·사후관리 | 대표 서사` 중 주 유형을 선택한다.
2. 제목에 숫자가 있으면 본문 답 개수도 확인한다.
3. 이 라이브러리에서 제목 약속과 답 개수가 가장 가까우며 꾸미기 프로필이 등록된 대표글 한 편을 주 마스터로 선택한다.
4. 주 마스터 원문 전체를 읽고 블록·문단·문장 역할 지도를 만든다. 보조 원문은 답의 누락·모호성을 확인할 때만 1편 추가하고, 주 마스터의 구조·말투·꾸미기를 대체하거나 섞지 않는다.
5. 마스터의 후킹 수, 감정선, 정보 공개 순서, 반론 처리, 소제목 수, 증거와 결론·CTA 위치를 그대로 유지한다.
6. 각 문장의 설득 역할은 유지하되 원문의 주제 내용은 새 제목의 내용으로 치환한다.
7. 사실은 최신 사실표에서 선택하고 레퍼런스의 과거 수치·시제는 사용하지 않는다.
8. 최근 글과 구조가 겹치더라도 선택한 마스터가 같다면 억지로 구조를 바꾸지 않는다. 새 제목의 독자 생각·사례·설명 명사·판단 내용으로 차이를 만든다.
9. 모든 글에서 같은 마스터 ID의 꾸미기 프로필을 읽고 정렬·크기·색·빈 줄·표·인용구·미디어 순서를 함께 재구성한다. 완성 article은 `scripts/build_naver_copy_page.py`로 네이버용 HTML 복사 페이지로 감싼 뒤 바탕화면에 저장한다.

## 토큰 사용 원칙

- 처음에는 이 목록만 읽어 후보를 좁힌다.
- 실제 작성 단계에서는 선택된 주 마스터 한 편과 그 마스터 구조를 해석하는 기록만 읽는다. 보조가 필요할 때만 같은 유형 원문 1편을 추가한다.
- 다른 유형의 전체 원문은 읽지 않는다.
- 같은 유형에서도 선택한 주 마스터 외의 원문은 필요할 때만 보조 1편까지 읽으며 총 원문은 2편을 넘기지 않는다.
- 꾸미기·사진·줄바꿈 검토는 주 마스터 1편과 그 프로필만 읽고 보조 원문을 열지 않는다.
- 프로필만 보고 쓰지 않는다. 말투와 문단 호흡을 재구성하려면 선택한 마스터 원문 전체를 반드시 읽는다.
