# 유형 레퍼런스 1대1 재구성

## 목적

새 제목과 같은 유형의 대표글 한 편을 주 마스터로 선택하고, 그 글의 말투·설득 구조·HTML 꾸미기를 1대1로 유지한 채 제목에 필요한 내용과 최신 사실만 치환한다. 주 마스터로 답이 모호하거나 사용자가 보강을 명시한 경우에만 같은 유형의 보조 원문 한 편을 추가로 확인할 수 있으며, 원문은 최대 2편까지만 읽는다.

이 모드는 여러 글의 장점을 조합하는 방식이 아니다. 선택한 한 편이 후킹, 대표 소개, 신뢰 근거, 본론, 마무리의 전체 구조를 결정한다.

## 기본 계약

다음 항목을 마스터 레퍼런스와 동일하게 유지한다.

- 첫 후킹의 문장 수와 역할
- 인용문·질문·단호한 판정의 순서
- 대표 소개가 등장하는 위치
- 공감 문단과 2차 후킹의 유무·위치
- 신뢰 근거, 사진, 표가 들어가는 위치와 역할
- 본론 소제목 수와 공개 순서
- 각 절에서 반론·원리·예외·행동이 등장하는 순서
- 대표 서사와 증거가 등장하는 위치
- 비교 권유와 CTA의 위치
- 짧은 문장과 긴 설명 문장의 교차 리듬
- 따옴표, 괄호 문단, 단독 한 줄 문장의 사용 위치
- HTML의 구성요소 순서, 정렬, 글자 크기 단계, 강조색, 배경 하이라이트, 빈 줄 호흡
- 표·인용구·사진·콜라주·캡션·지도·연락처의 개수와 위치
- 꾸미기 프로필에 등록된 사진의 정확한 원본 파일과 단독·콜라주 내부 순서

다음 항목만 새 제목에 맞게 바꾼다.

- 핵심 키워드와 지역·기종·상황
- 독자가 할 법한 생각과 질문의 실제 내용
- 본문에서 설명할 원인·방법·주의점
- 최신 판매량·정책·기간·수치
- 새 제목을 직접 답하기 위한 예시와 행동
- 근거가 달라졌을 때의 신뢰 사실과 캡션

고정 연락처와 네이버 예약 마감은 현재 운영 설정을 따른다.

## 마스터 선택

다음 순서로 가장 가까운 한 편만 선택한다.

1. 제목이 약속하는 답의 종류가 같은가
2. 글 유형이 같은가
3. 제목의 답 개수가 같은가
4. 첫 후킹 방식이 같은가
5. 본론의 설득 목적이 같은가
6. 신뢰 근거와 CTA의 역할이 같은가

첫 번째 후보가 충분히 맞으면 두 번째 글을 읽지 않는다. 두 번째 후보를 읽더라도 답의 누락·모호성만 확인하며 두 후보를 섞어 평균 구조를 만들지 않는다.

맞는 마스터가 없으면 다른 유형을 빌려 쓰지 않는다. 다음 형식으로 해당 유형의 레퍼런스를 요청한다.

```text
[추가로 필요한 자료]

1. 이 제목과 같은 [유형명] 대표글 1편
```

## 구조 맵

작성 전에 마스터 글을 다음 단위로 분해한다.

```json
{
  "masterReferenceId": "reference-id",
  "decorationMasterReferenceId": "reference-id",
  "articleType": "경고·피해예방형",
  "titlePromise": "독자에게 약속한 답",
  "blocks": [
    {
      "index": 1,
      "role": "판매자 멘트 후킹",
      "sentenceCount": 3,
      "tone": "짧은 인용 3개",
      "replacementContent": "새 제목에 맞는 세 멘트"
    }
  ],
  "fixedPositions": {
    "speakerIntro": 3,
    "secondHook": 5,
    "proof": 6,
    "cta": "last"
  }
}
```

완성 원고는 `blocks`의 개수와 순서를 바꾸지 않는다. 각 블록의 문장 역할과 문장 수를 유지하고 `replacementContent`만 새 제목에 맞게 쓴다.

HTML에서는 `decorationMasterReferenceId`가 `masterReferenceId`와 반드시 같아야 한다. 자세한 장식 맵과 복사 안전 예외는 [reference-decoration-profiles.md](reference-decoration-profiles.md)를 따른다.

## 꾸미기 맵

- 마스터 원문의 SmartEditor 구성요소 순서를 기록한다.
- 각 문장 역할에 연결된 정렬·크기·굵기·색·배경을 기록한다.
- 표의 개수와 행 수, 인용구 종류와 개수, 미디어와 캡션 위치를 기록한다.
- `mediaSlots`가 있으면 같은 `sourceUrl` 사진을 같은 구성요소 위치에 연결한다. 사용자 컴퓨터의 로컬 이미지 유무는 확인하거나 요구하지 않는다.
- 빈 문단 수와 줄바꿈 위치를 의미 덩어리 단위로 기록한다.
- 새 원고를 같은 슬롯에 넣고 다른 글의 장식이나 공통 템플릿을 섞지 않는다.
- 밑줄은 프로필에 등록된 문장 역할·위치·횟수대로 유지한다. 하이픈 빈 줄과 표 헤더 이중 배경만 사용자 승인 복사 안전 예외로 바꾼다.

## 후킹과 말투

- 마스터가 판매자 멘트 3개로 시작하면 새 글도 제목에 맞는 판매자 멘트 3개로 시작한다.
- 마스터가 독자의 의심 3개로 시작하면 새 글도 제목에 맞는 의심 3개로 시작한다.
- 마스터가 대표 소개로 시작하면 대표 소개 위치를 유지한다.
- 마스터에 소비자 마음 2차 후킹이 있으면 선택 압박 해제, 시간 요청, 이익 약속, 작성 명분의 기능과 순서를 그대로 유지한다.
- 마스터에 2차 후킹이 없으면 자동으로 추가하지 않는다.
- 마스터의 어미 비율, 질문 호흡, 단호한 한 줄, 괄호 문단 위치를 유지한다.
- 원문의 고유 문장을 통째로 붙이지 않고 같은 문장 역할을 새 제목의 내용으로 다시 쓴다.

## 본론

- 소제목 수는 마스터와 동일하게 유지한다.
- 소제목이 순위형이면 순위형, 질문형이면 질문형으로 유지한다.
- 각 절의 문단 수와 정보 공개 순서를 유지한다.
- 마스터의 첫 절이 위험 판정, 둘째 절이 손실 원리, 셋째 절이 선택권 설명이라면 새 글도 같은 기능 순서를 따른다.
- 제목의 답 개수와 마스터 소제목 수가 맞지 않으면 억지로 절을 추가·삭제하지 말고 더 가까운 마스터를 찾는다.
- 같은 내용을 표현만 바꿔 채우지 않는다. 각 블록에는 새 제목을 설명하는 실제 내용이 있어야 한다.

## 신뢰 근거와 사실

- 신뢰 근거의 위치와 표현 형식은 마스터를 따른다.
- 마스터가 사진 캡션 1개를 쓰면 현재 검증 사진과 캡션 1개를 같은 위치에 둔다.
- 마스터가 3행 또는 5행 표를 쓰면 현재 사실 중 제목과 가까운 항목으로 같은 역할의 표를 구성한다.
- 과거 판매량·문의량·정책 시제는 최신 사실로 교체한다.
- 레퍼런스의 사실을 그대로 복사하지 않고 `brand_facts.md`와 `temporary_information.md`의 현재값을 사용한다.
- 현재 근거가 없어 같은 위치를 채울 수 없으면 허위 대체물을 만들지 않고 자료를 요청한다.
- 단, 선택한 마스터의 `mediaSlots`에 이미 등록된 공식 블로그 사진은 재확인 없이 같은 파일을 그대로 사용한다.

## 자동 조합 금지

마스터에 없으면 추가하지 않는다.

- `반박분석 3멘트`를 마스터에 없는데 추가하지 않는다.
- `소비자 마음 2차 후킹`을 마스터에 없는데 추가하지 않는다.
- 별도의 마무리 공식을 마스터 CTA 위에 덧붙이지 않는다.
- 보조 원문을 읽었더라도 그 글의 문단·후킹·표·사진·꾸미기를 가져와 끼우지 않는다.
- 다른 유형의 말투·후킹·증거 구조를 섞지 않는다.
- 다른 유형의 색상 팔레트·표·인용구·사진 배치·공통 HTML 템플릿을 섞지 않는다.
- 사용자가 명시적으로 `두 글을 섞어 달라`, `하이브리드로 작성`이라고 요청한 경우에만 조합 모드를 사용한다.

## 길이와 SEO 적용

- 구조 블록을 추가하거나 삭제하지 않고 각 블록 안의 설명 밀도로 1,400~1,800자를 맞춘다.
- 정확 키워드 5회는 마스터의 서로 다른 내용 블록에 배치한다.
- 키워드 때문에 새 문단이나 요약 문장을 추가하지 않는다.
- 글자 수가 부족하면 마스터 블록 안에서 원인·예외·결과를 구체화한다.
- 구조를 유지한 채 분량을 맞출 사실이 부족하면 자료를 요청한다.

## 검문

- 주 마스터 레퍼런스가 정확히 한 편이고, 전체 원문을 읽은 원문 수가 최대 2편인가
- 마스터의 블록 개수와 완성 원고의 블록 개수가 같은가
- 후킹 문장 수와 역할이 같은가
- 대표 소개, 2차 후킹, 신뢰 근거, 소제목, 증거, CTA 위치가 같은가
- 본론 소제목 수와 각 절의 정보 공개 순서가 같은가
- 말투의 질문·단호한 문장·설명 문장 리듬이 같은가
- 새 제목과 맞지 않는 원문 내용이 남지 않았는가
- 오래된 사실을 최신값으로 교체했는가
- 보조 원문이 있다면 답의 누락·모호성 확인 외에 다른 레퍼런스의 기능을 섞지 않았는가
- 글쓰기 마스터와 꾸미기 마스터가 같은 ID인가
- 정렬·크기·색·강조·빈 줄·표·인용구·미디어 위치가 마스터 프로필과 같은가
- 등록 사진의 URL·순서·단독/콜라주 배치가 `mediaSlots`와 정확히 같은가
