# 청년통신 발행용 자연스러운 원고 파이프라인

## 목차

- 목적과 경계
- 사실 팩
- 제목 검증
- 말투 자료 선택
- 숨은 기획과 작성자 입력
- 후보 작성
- 독립 검수
- 부분 재작성
- 후처리와 발행 게이트

## 목적과 경계

기획, 글쓰기, 검수, SEO·미디어 편집을 한 번에 수행하지 않는다. 각 단계의 입력을 분리해 내부 평가표가 본문 문장으로 새는 것을 막는다.

기본 산출물은 독자가 바로 읽을 수 있는 발행 준비 원고다. 제작 메타데이터와 검수 결과는 본문과 분리한다.

## 사실 팩

작성 전에 다음 구조를 내부 작업 메모로 만든다. 사용자가 모든 항목을 주지 않아도 확인 가능한 범위에서 채운다.

```json
{
  "topic": "글의 주제",
  "title": "검증할 제목",
  "mainKeyword": "메인키워드",
  "articleType": "제목에서 자동 선택한 유형",
  "masterReference": {
    "id": "선택된 유형별 대표글 ID",
    "url": "선택된 원문 URL",
    "title": "마스터 제목"
  },
  "masterStructure": {
    "blockCount": 0,
    "hookSentenceCount": 0,
    "speakerIntroBlock": 0,
    "secondHookBlock": null,
    "headingCount": 0,
    "proofBlocks": [],

  },
  "speaker": {
    "name": "확인된 이름 또는 null",

    "phone": "010-8489-4440",
    "naverReservation": true
```

- 실제 고객 질문과 일반적인 독자 질문을 구분한다.
- 시점 민감 정보에는 확인 날짜 또는 만료 시점을 남긴다.
- 자료가 없으면 `null`로 두고 본문에서 만들지 않는다.
- 분량 목표 자체를 사실 팩의 사실로 취급하지 않는다. 각 핵심 답에 설명 재료가 두 종류 미만이면 초안을 쓰지 말고 필요한 사실을 요청한다.
- `reader.initialThoughts`는 매장 운영자의 관심사가 아니라 휴대폰을 계약하기 직전 또는 계약 뒤 청구서를 본 소비자의 입에서 나올 문장이어야 한다. `문의량·판매량·운영·확장`은 여기에 넣지 않는다.

## 제목 검증

제목을 문자 그대로 읽고 다음을 내부 메모로 만든다.

```json
{
  "literalPromise": "본문이 직접 답해야 할 한 문장",
  "claimEvidence": [{"claim": "제목 속 사실 주장", "factId": "F1"}],
  "answerCount": 3,
  "status": "pass | retitle"
}
```

- `상위 1%`, 판매량, 할인율, 손해액, 보장, 경력, 수상은 근거 ID가 없으면 `retitle`한다.
- `3가지`는 같은 말을 세 단계로 나눈 것이 아니라 독립된 답 세 개가 있어야 한다.
- 제목이 원인을 약속하면 원인을, 확인법을 약속하면 확인법을 쓴다. 서로 바꾸지 않는다.
- 제목의 주어가 사실상 매장이라도 독자가 얻는 답이 `문의가 많은 이유`, `운영을 잘하는 이유`뿐이면 `retitle`한다. 기기값·할부·요금제·부가서비스·계약서·반납처럼 구매자가 바로 확인할 대상을 제목의 답으로 바꾼다.
- 사용자가 제목을 고정하라고 했지만 근거가 없으면 필요한 근거를 요청하거나 사실 주장 없는 제목으로 바꿀 수 있는지 알린다.

## 말투 자료 선택

- 먼저 [type-reference-library.md](type-reference-library.md)에서 제목과 같은 주 유형을 찾는다.
- 제목 약속, 답 개수, 후킹 방식, 설득 목적이 가장 가까운 대표글 **한 편을 주 `master reference`**로 선택한다. 주 마스터가 충분하면 다른 원문을 읽지 않고, 모호성 확인이나 사용자 보강 요청이 있을 때만 같은 유형의 보조 원문 한 편을 추가해 원문 총 2편을 넘기지 않는다.
- 선택한 주 마스터 원문을 처음부터 끝까지 읽는다. 보조 원문은 답의 누락·모호성 확인이나 사용자의 명시적 보강 요청이 있을 때만 같은 유형으로 1편 추가하며, 같은 유형의 두 번째 글은 필요할 때만 보조 1편으로 읽고, 다른 유형 글은 읽거나 섞지 않는다. 원문 총 2편을 넘기지 않는다. 꾸미기·사진·줄바꿈은 주 마스터만 따른다.
- 마스터의 전체 블록 수, 문단 순서, 문장별 설득 역할, 소제목 수, 대표 소개, 2차 후킹, 증거, CTA 위치를 구조 지도로 기록한다.
- 3멘트·2차 후킹·마무리 분석 문서는 마스터 안에 해당 기능이 있을 때 그 기능을 해석하는 용도로만 읽는다. 그 문서에서 새 블록을 가져와 넣지 않는다.
- 외부 레퍼런스의 과거 사실과 주제 문장은 새 글로 옮기지 않는다. `cjdsus4444`의 청년통신 사실은 동일 항목의 최신 게시물을 기준으로 사실 팩에 넣고, 문장 역할은 유지한 채 새 제목의 내용으로 치환한다.
- 최근 글과 같아 보인다는 이유로 마스터의 소개 위치, 신뢰 근거 개수·위치, 소제목, CTA를 임의로 바꾸지 않는다.
- 유형 후보를 좁히기 전에는 전체 원문을 읽지 않는다. 라이브러리 목록에서 주 마스터 한 편을 선택한 뒤 그 원문만 불러오고, 정말 필요한 경우에만 보조 원문 한 편을 추가한다.
- 맞는 마스터가 없으면 다른 글을 조합하지 말고 같은 유형의 대표글 한 편을 요청한다.

## 숨은 기획과 작성자 입력

기획 메모에는 다음 일곱 가지 역할만 둔다.

1. 선택한 마스터 ID와 전체 구조 지도
2. 제목에 대한 직접 답
3. 독자가 현재 겪는 한 가지 상황
4. 사용할 사실·사례와 들어갈 마스터 블록
5. 독자가 할 한 가지 행동
6. 마스터에 2차 후킹이 있을 때 치환할 남은 저항
7. 마스터에 2차 후킹이 있을 때 본론 직전 약속할 검증 가능한 이익

제목에서 글 유형을 자동 선택한다. 이유·차이·구매법은 설명·가격 비교형, 사기·호구·손해·주의는 경고·피해예방형, 왜 싼지·방송·판매량·대표 신뢰는 권위·가격형, 사전예약·재고·입고는 사전예약·재고형, 질문·위치·영업시간·서비스센터는 FAQ·사후관리형, 대표 경력·철학은 대표 서사형으로 둔다. 신뢰 근거는 유형을 결정하는 논거로 세지 않는다.

모든 작성자 입력에 다음 컴포넌트를 내용 지시로 포함한다.

- 마스터의 신뢰 근거 블록과 같은 개수·형식·위치를 유지하고, 그 안의 사실만 제목과 가까운 최신 사실로 교체
- 본문 고유 결론 뒤 대표 전화 `010-8489-4440`, 부재 가능성, 네이버 예약 안내
- 마스터의 긴장 문장 수·위치·강도를 유지하고 새 제목에 맞는 강한 표현으로 치환. 마스터에 없으면 추가하지 않음
- 마스터에 `반박분석 3멘트`가 있으면 같은 위치와 문장 수로 서로 다른 세 멘트와 본문에서 회수할 세 답을 새 제목에 맞게 치환
- 마스터에 2차 후킹이 있으면 선택 압박 해제·짧은 시간 요청·검증 가능한 이익·놓칠 비용·작성 명분의 기능과 순서, 문장 수를 그대로 유지해 새 제목의 저항과 이익으로 치환. 마스터에 없으면 추가하지 않음
- 구체적인 절약액·기간·결과를 약속할 때는 독자의 결과 자체를 뒷받침하는 사실 ID를 연결. 매장 수수료 차이를 독자 절약 보장으로 확대하지 않음

정확 키워드를 본문에 사용한다면 [keyword-integration.md](keyword-integration.md)에 따라 이미 필요한 내용 문장 5개의 서로 다른 역할도 내부적으로 정한다. 키워드 전용 문장이나 SEO 보충 문단은 기획하지 않는다.

`role`, `actionId`, `closingJob`, `CHECK`, `공통 전제`, `판단 단위` 같은 기획어를 작성자 입력에 넣지 않는다.

작성자에게는 다음과 같이 구체적인 내용 메모만 전달한다.

```text
청년통신 대표가 [독자 상황]에 있는 고객 한 명에게 직접 설명한다.
제목이 약속한 답은 [직접 답]이다.
사용 가능한 사실은 [F1, F2]이고 실제 상담 재료는 [M1]이다.
마스터는 [ID/제목] 한 편이다. 다른 글을 섞지 않는다.
마스터의 [블록 수], [후킹 문장 수], [대표 소개 위치], [2차 후킹 유무와 위치], [소제목 수], [증거 위치], [CTA 위치]를 그대로 유지한다.
각 블록의 문장 수와 설득 역할도 마스터와 동일하게 유지하고, 내용만 새 제목과 최신 사실로 치환한다.
마스터에 2차 후킹이 있으면 [남은 저항]과 [본문에서 회수할 이익]으로 같은 기능·순서·문장 수를 유지한다. 없으면 넣지 않는다.
모든 문단은 새 사실·사례·설명·예외·행동 중 하나를 추가한다.
자료가 끝나면 글도 끝낸다.
표·사진 캡션·괄호 문단·마무리는 마스터에 있는 것만 같은 위치에 둔다.
본문만 작성한다.
```

작성자에게 독립 검수의 전체 오류 목록을 미리 주지 않는다.

## 후보 작성

- 새 글은 마스터 구조 지도에 맞는 후보 한 개만 작성한다.
- 첫 후킹을 쓰기 전에 마스터 각 후킹 문장의 `말하는 사람`, `불만 대상`, `본문에서 회수할 답`을 기록한다. 소비자 발화는 소비자 발화로, 판매자 반박은 판매자 반박으로 유지한다.
- 소비자 발화 자리에 브랜드 성과나 매장 운영 질문을 넣지 않는다. 휴대폰 구매자가 실제 상담 직전·계약 직후 말할 법한 구체 명사가 없는 후킹은 작성 단계에서 폐기한다.
- 도입 시작점, 화자 소개 위치, 신뢰 근거 개수·위치, 소제목 수, 2차 후킹 문장 수, 증거와 CTA 위치를 후보 차별화를 이유로 바꾸지 않는다.
- 제공되지 않은 실제 고객 발화나 대표 경험을 만들지 않는다.
- 번호 글이면 각 절의 문단 수·설명 순서·마지막 동사를 마스터의 대응 절과 같은 역할로 유지한다.
- 화자의 입장·양보·판단은 마스터에 나타나는 위치와 강도로 유지하되 새 제목의 판단으로 치환한다.
- 구조가 어긋나면 다른 후보를 만들지 말고 어긋난 블록만 마스터 지도에 맞게 되돌린다.

## 독립 검수

검수 단계에는 다음 네 가지만 전달한다.

1. 제목
2. 사실 팩
3. 선택된 마스터 원문과 구조 지도
4. 선택된 초안

의심 문장, 예상 정답, 작성자의 검수 결과는 전달하지 않는다. 검수자는 새 원고를 쓰지 않고 JSON만 반환한다.

```json
{
  "scores": {
    "titleMatch": 2,
    "factSafety": 2,
    "masterStructureFidelity": 2,
    "masterToneFidelity": 2,
    "informationProgress": 2,
    "spokenVoice": 1,
    "closingDiscipline": 1,
    "productionCleanliness": 2
  },
  "issues": [
    {
      "span": "문제가 있는 원문 그대로",
      "signals": ["master-structure-drift"],
      "reason": "짧은 이유",
      "action": "restore-master-role | replace-topic-content | fact-check | retitle"
    }
  ]
}
```

점수는 `0=발행 차단`, `1=수정 필요`, `2=통과`다. 모든 점수가 2일 때만 `issues`를 비울 수 있다.

검수 신호:

- `title-mismatch`: 제목 약속과 다른 답
- `unsupported-claim`: 근거 없는 수치·우월성·경험
- `semantic-duplicate`: 같은 뜻을 단어만 바꿔 반복
- `outline-leakage`: 글의 기능이나 순서를 설명하는 메타 문장
- `mixed-metaphor`: 같은 대상을 여러 비유로 바꿈
- `abstract-chain`: 구체 명사 없이 추상어가 이어짐
- `predicate-mismatch`: 주어·목적어·동사가 의미상 맞지 않음
- `dangling-reference`: 앞에 대상이 없는 `이것`, `이 세 가지`
- `seo-damage`: 키워드 때문에 조사나 문맥이 어색함
- `production-residue`: 사진 지시, 내부 라벨, 빈 칸
- `spoken-voice-fail`: 대표가 고객에게 소리 내어 말하기 어려움
- `master-reference-missing`: 같은 유형의 마스터 한 편이 선택되지 않았거나 원문 전체를 읽지 않음
- `master-structure-drift`: 블록 수·문단 순서·후킹 수·소제목 수·정보 공개 순서·증거·CTA 위치가 마스터와 다름
- `master-feature-added`: 마스터에 없는 3멘트·2차 후킹·별도 마무리·표·증거 블록을 다른 자료에서 가져와 추가함
- `master-tone-drift`: 질문, 단호한 한 줄, 괄호 문단, 짧고 긴 문장 호흡이 마스터와 뚜렷하게 다름
- `section-symmetry`: 마스터에는 없는 대칭 구조를 새로 만들었음. 마스터 자체의 반복 구조를 그대로 유지한 경우에는 오류가 아님
- `directive-repetition`: 마스터에는 없는 `확인하세요·요청하세요·보세요` 반복을 새로 만듦
- `conclusion-recap`: 결론이 번호 절이나 표를 다시 열거함
- `cta-stack`: 독자 행동·비교 권유·상담·예약을 겹쳐 붙임
- `brand-proof-missing`: 선택한 현재 신뢰 근거가 하나도 없음
- `brand-proof-stale`: 최신 사실 대신 과거 수치·시점 표현을 사용함
- `rebuttal-triplet-fail`: 세 멘트가 같은 뜻이거나 본문에서 하나 이상 회수되지 않음
- `second-hook-duplicate`: 2차 후킹이 첫 후킹의 의심을 다시 말할 뿐 새 이익이나 읽을 이유를 추가하지 않음
- `second-hook-empty-promise`: 본론에서 회수하지 않는 막연한 도움·절약·혜택을 약속함
- `second-hook-unsupported-payoff`: 금액·기간·결과 약속에 독자 결과를 뒷받침하는 현재 근거가 없음
- `industry-aside-forced`: 업계 긴장 문장이 제목·작성 명분과 무관하거나 특정 경쟁사를 근거 없이 단정함
- `fixed-contact-missing`: 대표 전화 또는 네이버 예약 마감이 빠짐
- `type-tone-mismatch`: 제목과 본문 유형이 다르거나 강한 표현을 엉뚱한 유형에 사용함
- `voice-dropout`: 이름과 인사말 뒤로 화자의 입장·판단이 사라짐
- `unsupported-example`: 사실 팩에 없는 수치·모델·상황을 실제 예시처럼 사용함

## 부분 재작성

- 지적된 문장과 앞뒤 문장만 편집한다.
- 정보 없는 반복은 다른 표현으로 고치지 말고 삭제한다.
- 추상어는 사실 팩의 실제 기종·금액·개월·서류로 바꾼다.
- 근거 없는 주장은 삭제하고 필요하면 제목을 다시 검증한다.
- 억지 비유는 새 비유로 교체하지 말고 제거한다.
- 문제가 없는 문단은 고정한다.
- `master-structure-drift`, `master-feature-added`, `master-tone-drift`는 마스터 구조 지도의 대응 블록으로 되돌리고 주제 내용만 다시 치환한다.
- `section-symmetry`는 마스터에 없는 대칭을 새로 만든 경우에만 마스터의 대응 절 구조로 되돌린다. 마스터에 있는 대칭은 고치지 않는다.
- `conclusion-recap`은 새 문장으로 바꾸지 않고 삭제를 우선한다.
- 부분 수정은 최대 두 번, 전체 재생성은 최대 한 번으로 제한한다.

## 키워드 통합, 후처리와 발행 게이트

본문 검수가 끝난 뒤에만 SEO, 표, 사진, GIF, HTML을 적용한다.

- 정확 키워드의 내용상 역할은 초안 전에 계획하고, 후처리에서는 횟수·분산·문법만 검증한다.
- 제목은 정확 키워드 1회, 표·캡션·연락처·지도·출처·CTA를 제외한 본문은 정확 키워드 5회로 맞춘다.
- 키워드 때문에 새 문장이나 새 문단을 만들지 않는다. 부족하면 이미 필요한 문단 전체를 다시 쓰고, 그래도 자연스러운 다섯 자리가 없으면 발행하지 않는다.
- 본문에서는 정확 키워드를 조사·시간 관계·구체적인 서술어와 연결한다. 행동형 키워드 뒤에 `상담·조건·견적·선택·비교·기준`을 조사 없이 이어 붙이지 않는다.
- 한 문단에는 한 번만 쓰고 도입·중간·후반에 분산한다. 정확 키워드로 시작하는 문단을 연속해서 만들지 않는다.
- 표는 실제 비교값이 있을 때만 사용한다.
- 미디어 목적과 자산 ID는 본문 밖의 데이터로 관리한다.
- `assetId: null`인데 마스터에 해당 미디어 슬롯이 있으면 필요한 실제 자료를 요청한다. 마스터에 미디어 슬롯이 없을 때만 생략한다.
- 실제 픽셀을 확인한 파일만 본문에 넣는다.
- 선택한 신뢰 근거 오버레이와 고정 연락·예약 마감을 최종 조립하고, 본문 중간의 중복 CTA를 제거한다.
- 파일 원고는 `scripts/validate_article.py`를 실행한다. HTML·미디어 진단이 필요할 때만 `scripts/validate_draft.py`도 실행한다.

다음은 발행 차단 오류다.

- 제목과 본문 답 불일치
- 근거 없는 수치·우월성·보장·경험
- 같은 의미의 결론 반복
- `CHECK`, 내부 JSON 키, 사진 번호, 선택 지시, 보이는 placeholder
- 키워드로 인한 문법 파손 또는 인접 문단 군집
- 본문을 그대로 반복한 표나 결론
- 가짜 고객 발화·대표 경험
- 선택한 현재 신뢰 근거 누락 또는 과거 수치·시점 표현 사용
- 같은 유형의 마스터 한 편 미선택 또는 마스터 원문 미확인
- 마스터와 다른 블록·문단·후킹·소제목·정보 공개·증거·CTA 순서
- 마스터에 없는 3멘트·2차 후킹·마무리·표·증거 블록 자동 추가
- 마스터와 뚜렷하게 다른 질문 호흡·단호한 문장·괄호 문단·문장 길이 리듬
- `반박분석 3멘트`의 세 멘트가 서로 겹치거나 본문에서 회수되지 않음
- 2차 후킹이 첫 후킹을 반복하거나 본론에서 회수하지 않는 막연한 이익을 약속함
- 구체적인 절약액·결과 약속에 현재 근거가 없거나 업계 긴장 문장이 특정 경쟁사를 단정함
- 대표 전화 `010-8489-4440` 또는 네이버 예약 고정 마감 누락
- 제목과 다른 글 유형 또는 중립 주제에 억지로 넣은 강한 표현
- 제목과 실제 본문 합계가 공백 제외 1,400자 미만 또는 1,800자 초과

오류를 수정하고 다시 검사한 뒤 완성 본문만 출력한다. 검수 보고와 미디어 작업 정보는 사용자가 요청한 경우에만 본문 밖에 제공한다.
