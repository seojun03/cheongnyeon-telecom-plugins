## 분석 범위

- 대상: `cjdsus4444` 공개 글 132개
- 미디어 사용: 1,161회
- 중복 제거한 고유 자료: 1,016개
- 글당 미디어: 평균 8.80개, 중앙값 8개
- 인덱스: `assets/media-library.json`
- 인덱스 근거: 원문 제목, 미디어 앞뒤 문장, 원래 위치, 파일 형식, 재사용 횟수

인덱스는 이미지 픽셀의 의미를 완전히 판독한 결과가 아니다. 제목이나 주변 문장이
잘 맞아도 최종 선택된 `sourceUrl`을 직접 열어 보고, 실제 화면이 인접 문단의 주장과
일치하는지 확인한다. 사용자 컴퓨터의 로컬 이미지 파일을 전제로 하지 않는다.

## 관찰된 배치 패턴

- 첫 미디어는 글 전체의 중앙값 5.56% 지점, 내용 문단 기준 중앙값 3개 뒤에 나온다.
- 첫 미디어의 55.3%는 내용 문단 3개 이내, 68.9%는 5개 이내, 82.6%는 8개 이내다.
- 첫 미디어 유형은 91.7%가 단일 이미지다.
- 인용·소제목 300개 중 80.3%는 다음 소제목 전에 미디어가 나온다.
- 소제목 바로 뒤 미디어가 21.7%, 설명 블록 1개 뒤 미디어가 51.7%다. 합계
  73.3%가 `소제목 → 설명 0~1개 → 미디어` 흐름이다.
- 2장 그룹은 이미지 그룹의 67.9%, 3장 그룹은 22.6%다.
- 지도 사용 글 50개 중 88%에서 지도가 마지막 미디어이고, 80%에서 연락·예약
  블록 뒤에 놓였다.
- 의미 있는 본문 GIF는 40회, 25개 글, 고유 자료 약 30개다. 상담·설정·매장
  증거 또는 단계 동작처럼 움직임 자체가 설명을 보완할 때 사용됐다.
- 장식 스티커 GIF는 2022년에 29회, 2023년에 4회였고 2024년 이후에는 관찰되지
  않았다. 현재 스타일에서는 사용하지 않는다.
- 권위 증명형은 글당 평균 10.29개, 정보형은 평균 8.87개의 미디어를 사용했다.
- 고유 자료 중 여러 글에 재사용된 비율은 7.97%뿐이다. 주제별 전용 자료가
  기본이고, 범용 증거 자료만 제한적으로 재사용한다.
- 캡션이 있는 미디어는 18.7%다. 캡션만으로 의미를 판단하지 말고 원문 제목과
  주변 문맥을 함께 사용한다.

수치는 새 글에서 그대로 맞출 할당량이 아니라 배치 리듬을 판단하는 근거다.

## 기본 배치 순서

선택한 마스터에 미디어가 있으면 아래 일반 순서보다 마스터의 미디어 슬롯 수·유형·위치를 우선한다. `mediaSlots`가 등록돼 있으면 각 슬롯의 같은 레퍼런스 블로그 `sourceUrl` 이미지를 그대로 배치한다.

1. 마스터의 첫 이미지가 나온 블록 뒤에 같은 역할의 단일 이미지를 둔다.
2. 선택한 마스터의 신뢰 근거가 생활의 달인 출연이고 검증된 사진이 있으면 마스터와 같은 위치에 둔다. 이후 정보형 이미지는 독자 문제·핵심 기준, 경고형은 위험
   상황, 권위형은 확장 신뢰 근거와 직접 연결한다.
   - 생활의 달인 사진은 그 사실을 말하는 문단 가까이에 둔다.
   - 사진 바로 아래에는 `SBS 생활의 달인 1029화 '휴대폰 달인' 출연`처럼
     확인된 사실만 짧게 캡션으로 적고, 곧바로 독자의 의심·문제로 넘어간다.
   - 사진이 없어도 같은 출연 사실을 대표 소개 문장에 사용할 수 있다. 이 경우
     관련 없는 대체 사진이나 빈 미디어 블록을 만들지 않는다.
   - 출연 사진과 사실 표의 유무·행 수·위치는 마스터를 따른다. 사진이 없으면 선택한
     사실을 텍스트로만 사용하고 관련 없는 이미지를 대신 넣지 않는다.
3. 각 인용·소제목 뒤 이미지의 위치는 마스터의 대응 소제목과 같은 블록 간격으로 둔다.
4. 2장·3장 그룹의 유무와 구성은 마스터를 따르고, 같은 역할의 최신 자료로 교체한다.
5. GIF는 마스터에 GIF 슬롯이 있고 움직임이 설명을 보완할 때 같은 위치에 둔다.
6. 결론, 대표전화·네이버 예약 블록, 지도의 순서와 유무는 마스터를 따른다.
8. 영상은 주제와 정확히 맞는 사용자 제공 자료가 있을 때만 사용한다.

## 자료 선택 원칙

추천 우선순위는 다음과 같다.

1. 기본 기준일에서 최근 18개월 안에 발행된 출처
2. 해당 문단 핵심어와 선택된 원문 제목·주변 문맥의 직접 일치
3. 실제 픽셀을 열어 확인한 장면과 바로 앞 문단의 의미 일치
4. 메인키워드와 주제의 직접 일치
5. 원문에서 관찰된 `intro`·`body` 위치 일치
6. 재사용 횟수가 적은 자료
7. 같은 글과 최근 원고에서 아직 쓰지 않은 자료

태그와 자산 전체 `searchText`는 동점 정리용이다. 여러 글에서 재사용된 자산의
통합 태그·키워드가 현재 문단과 맞더라도, 실제로 선택할 `sourcePosts` 항목의
`postTitle + context`에 문단 핵심어가 직접 나오지 않으면 자동 선택하지 않는다.

한 원고에서 같은 자산 ID를 두 번 쓰지 않는다. 마스터와 같은 미디어 슬롯 수를
유지하되 각 슬롯의 주제와 역할에 맞는 최신 검증 자료를 선택한다.

## 안전 규칙

- `sticker`, `map`, `og_image`, `video_thumbnail`, 영상은 자동 추천에서 제외한다.
- 지도는 자동 추천 자료가 아니다. `brand_facts.md`의 최신 공식 블로그 주소와
  매장 정보를 사용해 별도로 넣는다.
- 오래된 사전예약·이벤트·가격표·재고·지원금·요금제 화면은 현재 사실의 근거로
  재사용하지 않는다.
- 이미지 속 청년통신 정보는 같은 항목을 다룬 가장 최신 `cjdsus4444` 게시물과
  비교해 최신값을 사용하고 사용자 재확인을 요구하지 않는다. 명시된 과거 행사와
  기간은 현재 혜택으로 확대하지 않는다.
- 기본적으로 18개월보다 오래된 출처는 자동 추천에서 제외한다. 과거 회고나
  연혁처럼 옛 자료 자체가 주제일 때만 사용자가 허용한 기간으로 넓힌다.
- 이미지 안의 숫자, 가격, 정책, 판매량, 전화번호, 날짜를 읽어 새 글의 사실로
  옮기기 전에 최신 공개 근거나 사용자 자료로 확인한다.
- 특정 모델이 보이는 자료는 해당 모델이 주제에 명시됐을 때 우선한다. 다른 모델
  자료를 일반적인 최신 기기 사진처럼 쓰지 않는다.
- 추천된 `sourceUrl`을 직접 열어 보고 인접 문단과 맞지 않으면 다음 후보를 사용한다. 주 마스터의 등록 슬롯은 다른 후보로 교체하지 않는다.
- 적합한 자료가 없으면 관련 없는 사진으로 채우지 않는다. 추천 결과의
  `status: "placeholder"`는 내부 결손 상태로만 취급하고 보이는 본문에는 출력하지
  않는다. 필요한 장면은 본문 밖의 작업 메타데이터에 기록한다.
- 추천 결과에는 선택한 원문 발행일과 문맥 일치어를 남긴다. `최신 자료`라는
  표현은 이 발행일을 확인한 경우에만 사용한다.
- 출처 글의 문장과 주장을 복제하지 않는다. `sourcePosts`는 맥락과 출처 확인용이다.

## 추천 CLI

스킬 폴더에서 아래처럼 실행한다.

```bash
python3 scripts/recommend_media.py \
  --topic "휴대폰 계약 전 확인할 조건" \
  --keyword "광주휴대폰성지" \
  --mode warning \
  --count 6 \
  --include-gif \
  --format json
```

지원 모드:

- `information`: 설명·비교 정보형
- `warning`: 경고·피해예방형
- `authority`: 권위 증명형
- `draft`: 유형 미정 초안

최근 원고에서 사용한 자료는 반복해서 넘길 수 있다.

```bash
python3 scripts/recommend_media.py \
  --topic "아이폰 데이터 옮기는 방법" \
  --keyword "아이폰 데이터 이동" \
  --mode information \
  --count 8 \
  --include-gif \
  --long-form \
  --recent-id A00015 \
  --recent-id A00020 \
  --format markdown
```

- 기본 GIF 한도는 1개이며 `--long-form` 또는 자료 수 8개 이상이면 최대 2개다.
- `--recent-id`는 쉼표로 묶거나 여러 번 전달할 수 있다.
- `--as-of YYYY-MM-DD`로 오래된 이벤트 자료 판단 기준일을 고정할 수 있다.
- 기본 최신성 제한은 18개월이다. `--max-age-months`는 과거 자료 자체가 글의
  주제일 때만 명시적으로 늘린다.
- JSON의 `status: "placeholder"`는 적합도·안전 기준을 만족한 자료가 없다는 뜻이다.
  해당 결과의 placeholder 문자열을 발행 본문이나 HTML에 렌더링하지 않는다.
- `requiresVerification: true`인 자료는 이미지 안의 시점 민감 정보부터 확인한다.

## HTML과 네이버 게시

선택한 파일을 실제로 확인한 뒤 단일 미디어는 다음 원칙으로 렌더링한다.

```html
<figure data-cheongnyeon-media="A00000"
  style="margin:28px auto;text-align:center;max-width:860px;">
  <img src="[추천 결과의 sourceUrl]"
    alt="[확인한 실제 장면을 설명하는 짧은 문구]"
    style="display:block;width:100%;height:auto;margin:0 auto;" />
  <figcaption style="margin-top:8px;color:#777;font-size:13px;">
    [지역·업종 핵심어가 자연스럽게 들어간 사실형 캡션]
  </figcaption>
</figure>
```

- `data-cheongnyeon-media`에 자산 ID를 남겨 중복 여부를 추적한다.
- 로컬 HTML 미리보기와 네이버 복사 HTML은 같은 `sourceUrl`을 사용한다.
- `scripts/build_naver_copy_page.py`는 `data-reference-source-url`을 미리보기 `src`에도 적용하므로, 사용자 컴퓨터에 원본 이미지 파일이 없어도 같은 레퍼런스 이미지를 표시한다.
- GIF도 `<img>`로 배치하되 자동 재생이 설명에 꼭 필요한지 확인한다.
- 캡션은 실제 화면을 확인한 뒤 작성한다. 파일명이나 주변 문맥만 보고 장면을
  단정하지 않는다.

## 최종 검수

- 첫 미디어의 위치와 유형이 마스터와 같은가
- 전체 미디어 슬롯 수·그룹 수·GIF·지도 위치가 마스터와 같은가
- 각 이미지가 바로 앞 소제목이나 설명을 실제로 보완하는가
- 같은 자산 ID가 중복되지 않았는가
- 최근 원고의 자산 ID와 겹치지 않는가
- GIF가 장식이 아니라 동작 설명을 담당하는가
- 오래된 이벤트·모델·가격·정책 화면을 현재 정보처럼 쓰지 않았는가
- 모든 자동 선택 출처가 기본 18개월 제한을 통과했는가
- 선택된 `sourcePost`의 제목·주변 문맥에 해당 섹션의 직접 일치어가 있는가
- 모든 선택 파일을 직접 열어 실제 장면을 확인했는가
- 마스터의 미디어 슬롯에 맞는 실제 자료가 모두 있으며 보이는 placeholder가 남지 않았는가. 없으면 해당 자료를 요청했는가
