# 청년통신 블로그: 제목 공식

## 출처와 범위

- 기준 글: <https://blog.naver.com/sungji_dongtan/222515090668>
- 전체 공개 글 목록: <https://blog.naver.com/PostList.naver?blogId=sungji_dongtan&categoryNo=1&from=postList&parentCategoryNo=0>
- 압축 분석: `topic-idea-library.json`의 공개 글 188편
- 추출일: 2026-08-08
- 용도: 메인키워드 기반 주제·제목 장치·독자 질문·답변 의제 선택

자동모드는 반드시 `scripts/select_topic_idea.py`가 고른 프로필 한 편의 `titlePatternId`, `readerQuestion`, `answerAgenda`를 제목 설계의 출발점으로 쓴다. 정밀작성모드에서만 서로 다른 후보를 최대 3개 제시한다. 188편 원문 본문을 실행 때 다시 읽지 않는다.

기준 글의 정확한 제목은 `화성 핸드폰 가게, 상위 1% 매장에서 싸게 사는 법 알려드립니다`이다. 아래 훅과 문장 골격은 패턴으로만 참고한다. `화성`, `상위 1%`를 포함해 외부 글의 인물·업체·지역·숫자·순위·가격·보장·후기·경력은 청년통신 제목에 옮기지 않는다. 강한 슬롯은 `brand_facts.md`와 `temporary_information.md`의 사용 가능한 사실로 새로 채우거나 비수치 구매 질문으로 바꾼다.

## 공통 구조

관찰된 핵심 구조:

`앞쪽 메인키워드 1회 → 쉼표 또는 물음표 → 클릭 이유 → 독자가 얻을 답`

- 완성 제목은 공백 제외 22~40자를 권장하고 50자를 넘기지 않는다. 억지로 짧게 줄여 구체적인 클릭 이유를 지우지 않는다.
- 지역·업종 메인키워드를 가능한 한 제목 첫머리에 둔다.
- 쉼표는 검색어와 설명형 약속을 분리한다.
- 물음표는 검색 혼란, 의심 또는 위험을 열어 둔다.
- 후반부에는 이익, 손실, 확인 기준, 차이의 이유 또는 궁금증 중 하나만 중심으로 둔다.
- `알려드립니다`, `확인하세요`, `이유`, `기준`, `하는 법`처럼 본문에서 회수할 수 있는 말로 끝낸다.
- 같은 제목 안에서 메인키워드를 반복하지 않는다.
- 브랜드의 장점보다 구매자가 궁금해하는 `가격·제값·손해·약정·후회·견적·숨은 조건`을 제목의 주인공으로 둔다.
- `좋은 상담`, `선택 기준`, `사후관리`처럼 추상적이거나 구매 직전 관심도가 낮은 말은 기본 추천에서 뒤로 뺀다.
- `하루 문의 수`, `문의가 많은 이유`, `운영의 핵심`, `매장 확장`은 구매자의 검색 질문이 아니다. 회사 소개를 사용자가 직접 요청하지 않은 자동모드에서는 제목 후보에서 제거하고 신뢰 근거로만 쓴다.
- 브랜드 성과를 제목에 쓰려면 `그래서 구매자가 무엇을 덜 내거나 무엇을 확인할 수 있는가`가 같은 제목 안에서 바로 보여야 한다. 숫자 뒤에 `진짜 이유`만 붙여 구체성을 만든 것으로 보지 않는다.
- 제목을 선택하거나 바꾸면 제목만 교체하지 않고 본문 개요와 섹션 역할을 모두 다시 기획한다.

제목 후보를 만들기 전에 각 후보가 약속할 직접 답을 한 문장으로 적는다. 그 답과 근거를 실제로 쓸 수 없는 후보는 제거한다.

- 원인을 약속하면 실제 원인을 설명한다. 이를 확인 절차로 바꾸지 않는다.
- 확인법을 약속하면 독자가 실제로 물어보거나 볼 대상을 설명한다.
- `3가지`는 주제와 사실 팩에서 나온 서로 다른 답 세 개가 있을 때만 사용한다. 모든 글에 같은 세 항목을 적용하지 않는다.
- `이것`은 글 앞부분에서 실제 명사로 공개한다.

## 근거 기반 훅 모드

강한 훅은 패턴을 학습하는 자료일 뿐 최종 제목에 자동 채택하지 않는다.

- `100%`, `1억 배상`, `10명 중 9명/8명`, `10가지 중 9가지`, `수십만 원`, `상위 1%`, `7년/10년 경력`은 이번 작업의 검증된 사실 ID가 있을 때만 최종 후보에 사용한다.
- 질문형, 따옴표, 물음표는 근거 검증을 우회하는 장치가 아니다.
- 근거가 없으면 비수치·비최상급 제목으로 자동 변환한다.
- 자동모드는 한 편을 고르고, 정밀작성모드는 역할이 다른 세 유형을 고른다. 최근 3개의 `ideaType`, `titlePatternId`, `ideaReferenceUrl`을 우선 피한다.
- 사용자가 순수한 제목 패턴 탐색을 요청한 경우에만 미검증 골격을 `[근거 필요]`로 표시할 수 있다. 발행 제목 추천과 완성 원고에는 포함하지 않는다.
- 검증된 훅도 제목의 문자 그대로의 약속을 본문에서 답할 자료가 없으면 제외한다.

아래는 근거가 있을 때만 사용할 수 있는 패턴 예시다. 한 묶음에 모두 포함하지 않는다.

1. `상위 1%·구매법형`
   - `[메인키워드], 상위 1% 매장에서 싸게 사는 법`
2. `다수·과다지불형`
   - `[메인키워드], 10명 중 9명이 제값 내는 이유`
   - `[메인키워드]? 10명 중 8명이 놓친 '이것'`
   - `[메인키워드], 10가지 중 9가지를 놓치는 이유`
3. `손실액·이것형`
   - `[메인키워드]? '이것' 안 보면 수십만 원 날립니다`
4. `환불·보장형`
   - `[메인키워드], 2년 뒤 비싸면 100% 환불받는 곳`
   - `[메인키워드], 1억 배상·100% 환불 보장 매장?`
5. `경력·권위형`
   - `[메인키워드], 7년 한자리 대표가 거르는 조건 3개`
   - `[메인키워드]? 10년 차가 먼저 보는 기준 3가지`
6. `약정 후회·공통점형`
   - `[메인키워드], 약정 끝나고 후회하는 공통점`
7. `3가지·손실형`
   - `[메인키워드], 이 3가지 안 보면 돈 날립니다`
8. `시세표·호갱형`
   - `[메인키워드]? 시세표보다 '이것' 봐야 호갱 안 됩니다`

위 골격은 후보군이다. 한 번에 모두 복제하지 말고 메인키워드와 최근 사용 이력에 맞춰 자동모드는 한 프레임, 정밀작성모드는 서로 다른 세 프레임을 선택한다.

지역 키워드를 별도로 받으면 메인키워드에 포함됐는지 먼저 확인한다.

- 메인키워드 `휴대폰 성지`, 지역 `광주` → `광주 휴대폰 성지`
- 메인키워드 `광주휴대폰성지`, 지역 `광주` → `광주휴대폰성지`
- `광주 광주휴대폰성지`처럼 중복하지 않는다.

## 구매자 니즈형 확장 후보군

근거를 통과한 강한 훅과 아래 구매자 니즈형을 하나의 후보군으로 합친다. 최근 제목 메커니즘을 피하며 자동모드는 한 유형, 정밀작성모드는 서로 다른 세 유형을 고른다.

1. `10명·과다지불형`
   - `[메인키워드], 10명 중 9명이 제값 내는 이유`
   - `[메인키워드]? 10명 중 9명이 놓치는 기준`
2. `약정·후회공통점형`
   - `[메인키워드], 약정 끝나고 후회하는 공통점`
3. `싼 가격·숨은조건형`
   - `[메인키워드], 싸다는 말 뒤에 숨은 조건`
4. `같은 폰·가격차이형`
   - `[메인키워드], 같은 폰 가격이 다른 이유`
5. `속기 전·3가지형`
   - `[메인키워드], 속기 전에 찾을 3가지`
6. `상담대사·중단형`
   - `[메인키워드], 이 말 들으면 계약 멈추세요`
7. `시세표·이것공개형`
   - `[메인키워드]? 시세표보다 '이것' 먼저`
8. `제값·구매법형`
   - `[메인키워드], 제값 안 주고 사는 법`
9. `반납약속·함정형`
   - `[메인키워드], 반납 약속부터 의심할 이유`
10. `월 금액·총비용형`
   - `[메인키워드], 월 금액만 보면 손해 보는 이유`

- 완성한 뒤 `scripts/validate_title.py`로 공백 제외 길이·키워드·구체 훅·근거·외부 사실 유출을 검사한다.
- 40자를 넘으면 같은 메커니즘 안에서 자연스럽게 압축하고, 50자를 넘으면 발행하지 않는다.
- 정밀작성모드의 세 제목은 `patternId`와 구매자 효익이 서로 달라야 한다.
- `3가지`는 본문에 실제로 서로 다른 답 세 개가 있을 때만 사용한다.
- `연 8,000대`, `3년 서비스센터 무상 대행`, `청년통신`은 기본 제목 슬롯에 강제하지 않고 제목에 맞춰 선택한 본문 신뢰 근거에서 사용한다.
- `100%`, `1억 배상`, 비율, 손해액, `상위 1%`, 경력은 이번 작업의 근거 ID가 연결된 경우에만 후보군에 유지한다. `호갱`처럼 사실 수치가 아닌 경고어는 안전 규칙 안에서 사용할 수 있다.
- 근거 없는 훅은 발행 제목 후보에서 제거한다. 패턴 탐색 요청에서만 `[근거 필요]`로 분리한다.
- 새로고침할 때는 최근 작성 제목과 최근 추천 묶음을 피하되 메인키워드는 제목 앞부분에 정확히 한 번 유지한다.

## 검수

- 제목 첫부분에 메인키워드가 한 번만 있는가
- 공백 제외 22~40자를 권장하고 50자를 넘지 않는가
- 정밀작성모드의 3개 추천은 클릭 이유가 서로 다른가
- 브랜드 자랑보다 구매자의 가격·손실·후회·비교 욕구가 앞서는가
- 제목에서 `문의·운영·확장·표창`을 지워도 구매자가 얻을 답이 남는가. 남지 않으면 브랜드 중심 제목이므로 폐기했는가
- 지역 키워드가 중복되지 않았는가
- 숫자·순위·보장·경력·손해액이 검증된 사실 ID와 연결됐는가
- 질문형이나 물음표로 근거 검증을 우회하지 않았는가
- 제목 후보마다 본문에서 실제로 답할 한 문장을 적을 수 있는가
- `이것`, `이유`, `3가지`, `하는 법`의 답을 본문에서 회수하는가
- 제목 선택 후 H1뿐 아니라 본문 플로우도 다시 설계했는가
- 외부 아이디어 글의 지역·업체·인물·수치·순위·보장·경력·후기가 들어오지 않았는가
- `scripts/validate_title.py`를 통과했는가
