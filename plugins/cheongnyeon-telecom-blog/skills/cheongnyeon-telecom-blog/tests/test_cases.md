# 검수 테스트 케이스

`python3 -m unittest discover -s tests -p 'test_*.py' -v`로 자동 테스트를 실행한다. 아래 케이스는 원고 작성 규칙이 바뀔 때 유지해야 할 최소 회귀 범위다.

1. 정상적인 `질문 3가지` 원고: 1,400~1,800자, 제목 키워드 1회, 본문 5회, 세 답, 선택한 마스터와 동일한 절 구조 → `pass`
2. 제목은 3가지인데 번호 답이 2개뿐인 원고 → `title-section-count`
3. 본문 정확 키워드가 0회인 원고 → `body-keyword-count`
4. 본문 정확 키워드가 6회인 원고 → `body-keyword-count`
5. 키워드 문단이 연속한 원고 → `adjacent-keyword-paragraphs`
6. 제목과 본문 합계가 공백 제외 1,400자 미만 → `article-too-short`
7. 제목과 본문 합계가 공백 제외 1,800자 초과 → `article-too-long`
8. 스타일 예시에만 있고 사용 가능한 근거에는 없는 `90만원` 사용 → `unsupported-numeric-claim`
9. 마스터에는 없는 대칭 구조를 새로 만든 원고 → `master-structure-drift`; 마스터 자체의 반복 구조를 유지한 경우 허용
10. `상담 현장` 라벨과 마크다운 표가 본문에 포함됨 → `production-label`, `table-present`
11. 제목에 `이것`이 있으나 도입 첫 두 문단에서 실제 명사를 공개하지 않음 → `this-not-revealed`
12. 대표의 1인칭 화자가 본문에서 사라짐 → `speaker-missing`
13. 제로폭 문자·특수 공백·CRLF가 섞인 정확 키워드 → 정규화 뒤 올바르게 집계하고 `pass`
14. 현재 `사용 가능` 근거에 있는 수치 → `unsupported-numeric-claim` 없이 통과
15. 만료일이 지난 `사용 가능` 근거 → 근거 목록에서 제외
16. CTA와 사진 캡션에 들어간 정확 키워드 → 본문 5회 집계에서 제외
17. 발행 모드에서 현재 신뢰 근거가 하나도 없음 → `brand-proof-missing`
18. 발행 모드에서 신뢰 근거 1개가 후반에 있고 연락·예약 마감이 있음 → 위치 오류 없이 허용
19. `반박분석 3멘트`가 판매자 멘트형·독자 반론형과 두 기준 글을 모두 참조함 → 스킬 계약 테스트 통과
20. 첫 후킹 뒤의 2차 후킹이 같은 의심만 반복함 → `second-hook-duplicate`
21. 매장 수수료 30만 원 차이를 모든 독자의 최소 30만 원 절약으로 확대함 → `second-hook-unsupported-payoff`
22. 같은 유형의 마스터 한 편만 선택하고 기능 레퍼런스를 자동 조합하지 않는 규칙 누락 → 스킬 계약 테스트 실패
23. 새 제목의 유형을 고르기 전에 모든 레퍼런스 원문을 읽음 → 유형 라이브러리 선택 규칙 실패
24. 같은 유형의 가장 가까운 주 마스터 한 편을 전체 읽고, 필요할 때만 보조 한 편까지 확인하며 꾸미기는 주 마스터만 복제 → 토큰 선택 계약 통과
25. 마스터에 없는 `반박분석 3멘트`, `2차 후킹`, 마무리 또는 증거 블록을 추가함 → `master-feature-added`
26. 마스터와 블록 수·문장 역할·소제목·증거·CTA 위치가 다름 → `master-structure-drift`
27. 마스터와 질문 호흡·단호한 문장·괄호 문단·문장 길이 리듬이 다름 → `master-tone-drift`
