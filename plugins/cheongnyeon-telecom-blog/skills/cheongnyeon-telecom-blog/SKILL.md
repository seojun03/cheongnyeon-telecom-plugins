# 청년통신 블로그

청년통신 대표가 실제 상담 고객 한 명에게 설명하는 것처럼 쓴다. 내부 기획표, 검수 항목, SEO 작업, 미디어 지시는 완성 본문에 노출하지 않는다. 기본 발행 원고는 자료 충분성 게이트를 먼저 통과하고 제목과 실제 본문을 합쳐 공백 제외 1,400~1,800자로 완성한다.

## 모델 품질 권장 안내

이 스킬은 **모든 모델과 추론 수준에서 실행한다.** `GPT-5.6 Sol + High 이상`은 글 품질을 위한 권장 조건일 뿐 실행 조건이나 중단 게이트가 아니다. 스킬 지침과 `agents/openai.yaml`은 실행 중인 호스트 모델을 자동 변경할 수 없으므로 모델 전환을 요구하지 않는다.

1. 호스트 런타임 정보나 사용자가 제공한 현재 작업의 모델 선택 화면에서 `GPT-5.6 Sol + High·XHigh·Max 중 하나` 또는 그보다 상위인 모델·추론 수준이 명확히 확인되면 경고 없이 아래 실행 모드로 진행한다. `5.6 Sol High`처럼 화면에 축약 표기된 현재 작업 증거도 유효하다.
2. 현재 모델이나 추론 수준이 권장 조건보다 낮은 것으로 **명확히 확인된 경우에만** 다음 안내를 사용자 응답 상단에 정확히 한 번 출력하고, 같은 응답에서 정상 작업을 계속한다.

`참고: 글 퀄리티를 위해 GPT-5.6 Sol High 이상 모델을 사용해주시면 좋습니다. 현재 모델에서도 작업은 계속 진행합니다.`

3. 런타임 정보를 확인할 수 없으면 낮은 모델이라고 추측하거나 사용자에게 모델 확인을 요구하지 않는다. 경고 없이 정상 작업을 계속한다.
4. 어떤 모델에서도 모드 질문·레퍼런스 선택·제목·본문·HTML 생성을 차단하지 않는다. 안내 문구는 한 실행당 한 번만 사용자 응답에 표시하고 원고 본문이나 HTML에는 넣지 않는다.

## 실행 모드 인터뷰와 자동 이력

스킬을 새로 실행할 때는 본문을 쓰기 전에 반드시 다음 한 문장으로 모드를 묻는다.

`1. 자동모드  2. 정밀작성모드`

- **자동모드**: `scripts/select_topic_idea.py`를 실행해 `state/recent-articles.json`의 최근 3개 `ideaType`, `titlePatternId`, `ideaReferenceUrl`과 겹치지 않는 외부 아이디어 프로필 한 편을 우선 선택한다. 그 프로필의 제목 장치·독자 질문·답변 의제만 사용해 메인키워드와 제목을 만든 뒤 `scripts/validate_title.py`를 통과시킨다. 다음으로 호환되는 청년통신 주 마스터 한 편을 골라 본문·꾸미기·HTML을 한 번에 만든다. 완성 게이트를 통과한 뒤 `scripts/record_article_state.py`로 아이디어 출처와 글쓰기 마스터를 맨 앞에 기록하고 가장 오래된 항목을 지워 항상 3개만 유지한다. 기록에는 원고 본문이나 사실을 저장하지 않는다.
- **정밀작성모드**: 키워드 → `select_topic_idea.py --count 3`이 반환한 주제·제목 아이디어 3개와 각 원문 링크 → 제목 → 호환되는 청년통신 글 유형·주 마스터 링크 순으로 한 번에 하나씩 묻는다. 이어서 제목의 답을 강화할 추가 사실·대표 판단·독자 행동을 묻고, 사용할 이미지가 있으면 원본 파일·위치·캡션을 확인한 뒤 작성한다. 외부 아이디어 링크와 청년통신 주 마스터 링크를 같은 레퍼런스로 표시하지 않는다. 답변이 없는 항목은 추측하지 않는다.
- 이미 모드가 대화에서 명시된 경우에는 같은 질문을 반복하지 않고 해당 모드의 다음 단계로 진행한다. 자동모드가 제목·키워드를 정했을 때도 발행 직전에 사용자가 제공한 고정 사실과 최신 공식 블로그 사실을 우선한다.

### 자동모드의 구매자 관심도 게이트

최근 3개와 다른 유형을 고르는 일은 구매자 관심도보다 뒤에 둔다. 겹치지 않는다는 이유만으로 독자가 궁금해하지 않는 주제를 채택하지 않는다.

1. 제목 후보마다 `지금 휴대폰을 사려는 사람이 이 제목을 보고 바로 떠올릴 돈·계약·요금·기기·손해·행동은 무엇인가?`에 한 문장으로 답한다.
2. 답이 `매장 운영`, `문의 수`, `방문자 수`, `매장 확장`, `표창`, `판매자의 노력`뿐이면 후보를 폐기한다. 이 항목들은 제목의 답이 아니라 신뢰 근거 블록에서만 쓴다.
3. 회사·대표 소개형을 사용자가 명시적으로 요청한 경우에만 브랜드 성과 자체를 제목으로 허용한다. 이 경우에도 구매자에게 어떤 차이로 돌아오는지 제목에서 즉시 이해되어야 한다.
4. `하루 81건 문의`, `문의가 남는 이유`, `문의의 핵심은 운영`, `가격보다 좋은 상담`처럼 브랜드에는 의미가 있어도 구매 직전의 손실·의문·행동이 보이지 않는 후보는 자동모드에서 금지한다.
5. 최근 이력과 모두 겹쳐도 구매자 관심도가 높은 기존 유형을 다시 쓰는 편이 낫다. 다양성을 만들기 위해 독자 관심이 낮은 유형으로 도망가지 않는다.

9. **레퍼런스 밑줄 고정**: 밑줄을 공통으로 제거하거나 전체 문단에 추가하지 않는다. 꾸미기 프로필의 `requiredUnderlineRoleCounts`에 등록된 문장 역할만 `<u data-reference-underline-role="...">`로 같은 위치와 횟수에 밑줄 처리한다.
10. **첫 후킹의 독자 소유 원칙**: 마스터의 첫 후킹이 소비자의 실제 불만·의심·두려움을 인용한다면 새 글도 같은 수의 문장을 휴대폰 구매자 1인칭 생각으로 쓴다. `기기값·할부원금`, `안내받은 요금제·실제 청구`, `부가서비스·반납·유지 조건`, `추천받은 상품이 나에게 맞는지`처럼 구매자가 계약 전후 직접 겪는 대상을 포함해야 한다. 매장 운영자가 궁금해할 `문의량·판매량·운영·박리다매·확장·표창`을 소비자 마음처럼 꾸미지 않는다.
11. **후킹 역할 1대1 치환**: 초안 전에 주 마스터 첫 후킹 각 문장의 역할을 짧게 기록한다. 예를 들어 `안내 금액과 문서 금액의 불일치 → 설명한 요금과 실제 청구의 불일치 → 추천 조건에 대한 의심`이면 새 글도 이 세 역할을 같은 순서로 치환한다. 주제만 비슷한 추상 질문 세 개로 바꾸지 않는다.

신뢰 근거는 마스터가 사용한 사진 캡션, 대표 소개 문장, 짧은 목록, 네이버 기본 표 형식과 위치를 유지한다. 검증된 생활의 달인 사진을 선택했다면 사진 바로 아래에 `SBS 생활의 달인 1029화 '휴대폰 달인' 출연` 캡션을 붙인다. 사진이 없으면 관련 없는 대체 이미지를 만들지 않는다. 대표 소개도 마스터와 같은 위치와 문장 역할로 둔다.

## 우선순위

충돌할 때 다음 순서로 판단한다.

1. 확인된 사실과 사용자 지시
2. 제목이 문자 그대로 약속한 답
3. 선택한 마스터 한 편의 1대1 구조·말투·꾸미기
4. 독자 한 명에게 말하는 자연스러운 한국어

## 기본 출력 모드

자동모드와 정밀작성모드를 포함한 모든 완성 글은 `발행 준비 원고 + 바탕화면 네이버용 HTML 파일`을 기본 산출물로 한다. 사용자가 일반 텍스트만 보여 달라고 해도 HTML 파일은 함께 만들며, 사용자가 명시적으로 HTML 파일을 만들지 말라고 한 경우에만 생략한다.

- 텍스트 검수와 발행 게이트를 먼저 통과시킨 뒤 선택한 마스터의 장식 맵으로 완성 `<article>`을 만든다. 임의 공통 템플릿을 새로 만들지 않는다.
- 선택한 마스터의 꾸미기 프로필이 있으면 반드시 읽고, 없으면 원문 SmartEditor DOM을 분석해 프로필을 먼저 만든 뒤 HTML을 만든다. 프로필 없이 일반 카드·박스 스타일을 추측하지 않는다.
- 완성된 article fragment를 임시 파일로 저장하고 다음 빌더를 항상 실행한다.
  `python3 scripts/build_naver_copy_page.py --title "제목" --article-html "article-fragment.html" --reference-url "마스터 URL" --reference-label "마스터 표시명"`
- 이 문서의 `python3` 명령은 macOS·Linux 기준 예시다. Windows PowerShell에서는 같은 스크립트를 `py -3`으로 실행하고, `py`가 없지만 Python이 PATH에 있으면 `python`을 사용한다. 명령 이름 차이 때문에 작업을 중단하지 않는다.
- 출력 경로는 빌더가 현재 사용자의 바탕화면에서 자동 결정한다. 같은 이름이 있으면 `_2`, `_3`처럼 충돌을 피한 새 파일을 만든다. 테스트·사용자 지정 저장에는 `CHEONGNYEON_OUTPUT_DIR` 또는 `--output`을 사용한다.
- `<article data-master-reference-id="...">`의 모든 이미지는 선택 마스터 `mediaSlots`의 정확한 레퍼런스 블로그 `sourceUrl`을 `src`와 `data-reference-source-url`에 함께 사용한다. 미리보기와 네이버 복사 모두 같은 원본 URL을 사용하며 사용자 컴퓨터의 로컬 이미지 파일을 요구하지 않는다.
- 결과 페이지에는 `네이버용 HTML 복사` 버튼, `ClipboardItem`의 `text/html`·`text/plain` 복사와 fallback, U+2060 빈 줄 보존, 원본 미디어 URL 복원, `<article>`만 복사하는 범위가 모두 있어야 한다. 툴바·안내문·레퍼런스 카드는 복사하지 않는다.
- HTML은 [references/reference-decoration-profiles.md](references/reference-decoration-profiles.md)의 같은 마스터 장식·사진·밑줄·표를 1대1로 적용한다. 완성 파일은 `scripts/validate_reference_decoration.py`와 `scripts/validate_article.py`를 모두 실행한다.
- 완성 본문에 `[사진 선택]`, `[브랜드 정보 입력 필요]`, `사진 6`, `관련 확인 이미지`, `CHECK 01` 같은 제작용 문구를 남기지 않는다.
- 실제 미디어가 없으면 관련 없는 사진이나 보이는 placeholder를 넣지 않는다. 마스터에 필수 슬롯이 있는데 원본 자산을 확보할 수 없으면 HTML을 완성본처럼 제시하지 말고 해당 사진만 요청한다.
- 사실이 부족하면 원고를 일부라도 쓰지 않는다. `[추가로 필요한 자료]` 아래에 제목의 답을 완성하는 데 필요한 사실만 번호로 요청한다.
- 발행 게이트 또는 HTML·복사 검사를 통과하지 못한 결과를 완성본처럼 제시하지 않는다. 안전하게 자동 수정할 수 없을 때만 부족한 사실·자산을 짧게 알린다.

## 사실 입력

작성 전에 [templates/article_request.md](templates/article_request.md) 또는 [templates/fact_intake.md](templates/fact_intake.md)의 항목으로 입력을 나눈다. 자세한 스키마는 자연스러운 원고 파이프라인을 따른다.

- 제목 또는 주제와 메인키워드
- 화자의 이름·역할·입장
- 독자의 현재 상황과 이해 수준
- 검증된 브랜드 사실·숫자·정책
- 실제 고객 질문·상담 장면·사용 가능한 예시
- 독자가 읽은 뒤 할 한 가지 행동
- 근거가 없어 쓰면 안 되는 주장
- 고정값과 다른 CTA·연락 정보를 요청할 때의 변경 내용
- 사용할 수 있는 표·사진·GIF 근거

확정 제목, 정확 메인키워드, 화자 역할, 제목이 약속한 실제 답, 각 답의 확인된 설명 재료, 대표의 판단, 독자 행동을 필수로 확인한다. 각 핵심 답에는 `차이가 생기는 원인`, `서류에서 볼 항목`, `적용되지 않는 경우`, `고객에게 생기는 결과`, `확인된 대표 판단` 중 최소 두 가지가 있어야 한다. 하나라도 부족하면 초안을 만들지 않는다.

사실 우선순위는 `이번 대화에서 사용자가 직접 정정한 내용 → cjdsus4444의 동일 항목 중 가장 최신 게시물 → 충돌하지 않는 cjdsus4444 이전 게시물 → 기타 사용자 자료 → 외부 스타일 참고자료`다. 외부 스타일 참고자료의 판매량, 가격, 할인, 후기, 방송, 책임, 경험은 새 글의 사실로 옮기지 않는다.

초안이 있으면 고유명사, 숫자, 핵심 의미를 보호한다. `cjdsus4444`에서 확인된 사실은 재확인하지 않고 최신 관련 글로 충돌만 해결한다. 그 밖의 근거 없는 주장이나 최신성이 필요한 정책·가격은 확인하거나 삭제·완화한다. 자료가 적어도 허위 사례로 늘리지 않는다.

## 발행 원고 작성 순서

새 글과 실질적 리라이팅은 다음 단계를 분리해 수행한다.

1. **아이디어 프로필 선택**: `scripts/select_topic_idea.py`로 외부 주제·제목 아이디어 한 편을 고르고 `ideaReferenceId`, `ideaType`, `titlePatternId`, `readerQuestion`, `answerAgenda`를 고정한다. 외부 원문의 사실과 문장은 버린다.
2. **사실 팩 작성**: 확인된 청년통신 사실, 실제 장면, 금지 주장을 구조화한다.
3. **제목 생성·검증**: 선택된 제목 장치와 답변 의제를 메인키워드에 맞게 재설계한다. 제목이 약속한 답을 한 문장으로 적고 `scripts/validate_title.py`로 구체성·외부 사실 유출·근거·키워드를 검사한다.
4. **청년통신 마스터 한 편 선택**: 선택기가 반환한 호환 ID 중 제목의 답 개수·후킹 방식·설득 목적이 가장 가까운 `cjdsus4444` 글 한 편을 주 마스터로 고른다. 주 마스터만으로 충분하면 다른 원문을 읽지 않고, 답이 모호하거나 사용자가 보강을 명시한 경우에만 같은 유형의 보조 원문 1편을 추가해 청년통신 원문 총 2편을 넘기지 않는다. 두 글의 구조·꾸미기를 자동으로 섞지 않는다. 맞는 마스터가 없으면 다른 유형으로 작성하지 말고 해당 유형의 청년통신 대표글을 요청한다.
5. **1대1 구조 맵 작성**: 마스터의 블록 개수, 후킹 문장 수, 대표 소개, 2차 후킹 유무, 신뢰 근거 위치, 소제목 수, 각 절의 문장 역할, 증거와 CTA 위치를 순서대로 기록한다. 정확 키워드가 들어갈 서로 다른 다섯 블록도 지정한다. 항상 같은 마스터의 구성요소 순서, 정렬, 글자 크기, 강조색, 배경, 빈 줄 수, 표 행 수, 인용구·미디어·캡션·지도 위치를 장식 맵에 함께 기록하고 등록된 `mediaSlots`의 원본 사진 URL을 그대로 연결한다.
6. **내용 치환 초안 작성**: 구조 맵의 블록 개수·순서·문장 역할·문장 수를 유지하면서 새 제목의 독자 생각, 청년통신 사실, 설명, 행동으로만 바꾼다. 다른 구조 후보를 만들지 않는다. 표현 후보가 필요하면 같은 구조 안에서 어휘만 비교한다.
7. **독립 검수**: 제목·사실 팩·선택한 청년통신 마스터 원문과 구조 맵·초안을 새 검수 패스에 전달한다. 작성자의 자기평가, 정답 예시, 의심 구간은 전달하지 않는다.
8. **부분 재작성**: [templates/revision_request.md](templates/revision_request.md)에 실패 코드와 문단을 기록하고 지적된 문장과 필요한 앞뒤 문장만 삭제·병합·구체화한다. 문제가 없는 문단은 고정한다. 전체 재생성은 제목이나 논리가 바뀔 때만 한다.
9. **SEO·미디어·HTML 후처리**: 정확 키워드 횟수와 배치만 검증하고, 부족하다고 새 문장이나 새 문단을 덧붙이지 않는다. 본문을 반복하는 표는 넣지 않는다. HTML은 같은 마스터의 장식 맵에 문장을 넣는 후처리이며, 임의 디자인을 새로 만드는 단계가 아니다. 등록 사진은 같은 원본 URL·같은 위치·같은 순서로 삽입한다. article fragment를 만든 뒤 `scripts/build_naver_copy_page.py`로 현재 사용자의 바탕화면에 네이버용 복사 페이지를 저장한다.
10. **발행 게이트·이력 기록**: 제목, 사실성, 제목-본문 일치, 의미 중복, 제작 흔적, 키워드 문법을 다시 확인한다. 파일 원고는 `scripts/validate_article.py`를, HTML은 `scripts/validate_reference_decoration.py`를 실행하고 실제 복사 버튼·MIME·모바일 줄바꿈까지 확인한다. 통과 뒤에만 `scripts/record_article_state.py`로 아이디어 출처·제목 패턴·청년통신 주 마스터를 기록한다. 기존 HTML·미디어 원고의 보조 진단에만 `scripts/validate_draft.py`를 추가로 사용한다.

동일 작성자가 같은 문맥에서 자기 글을 검사하는 것은 독립 검수가 아니다. 별도 에이전트를 사용할 수 없으면 계획을 보지 않는 새 검수 패스로 초안 본문만 다시 읽고 같은 기준을 적용한다.

## 제목 계약

제목을 말투 장식이 아니라 본문이 이행할 구체적인 약속으로 취급한다.

- `가격 차이 3가지`라면 실제 가격 차이가 생기는 서로 다른 원인 세 가지를 설명한다. 이를 임의로 견적 확인 세 단계로 바꾸지 않는다.
- `상위 1%`, 비율, 판매량, 손해액, 경력, 환불·배상·보장, 수상은 근거 ID가 있을 때만 최종 제목에 사용한다.
- 외부 아이디어 글 제목에 있는 숫자·순위·경력·보장·인물·업체·지역은 패턴 슬롯이 아니라 폐기 대상이다. 같은 제목 장치를 쓰더라도 그 자리는 검증된 청년통신 사실 또는 비수치 구매자 질문으로 새로 만든다.
- 근거 없는 제목은 본문으로 얼버무리지 말고 증명 가능한 제목으로 먼저 고친다.
- `3가지`는 주제에서 실제로 도출되는 세 답이 있을 때만 쓴다. 모든 글을 `조건 통일 → 총비용 → 계약서 대조`로 고정하지 않는다.
- `이것`은 글 앞부분에서 실제 명사로 공개한다.
- 제목의 숫자와 본문이 실제로 답하는 항목 수를 맞춘다.
- 제목을 바꾸면 본문도 제목의 새 약속에 맞춰 다시 기획한다.
- `가격보다 상담 과정을 먼저 볼 이유`, `싼 곳이 의심될 때 확인할 근거`, 맥락 없는 `선택 기준`처럼 제목만 보고 답을 예상할 수 없는 추상 문구는 사용하지 않는다.

## 피해야 할 AI식 흔적

다음은 단어 금지 목록이 아니라 삭제·구체화해야 할 의미 신호다.

- 내부 설계 누출: `첫 번째 점검은 ~하는 일입니다`, `세 기준이 완성됩니다`
- 의미만 바꾼 반복: 본문, 표, 결론에서 같은 조언을 세 번 설명함
- 혼합 비유: 같은 대상을 `답 → 칸 → 방향 → 완성`으로 연속해서 바꿈
- 추상어 연쇄: `기준·조건·판단·기록`만 있고 실제 기종·금액·개월·서류가 없음
- 추상 명사 대조형 마무리: `답변과 서류`, `조건과 계약서`, `설명과 서류`가 맞거나 같으면 결정해도 된다는 식으로 끝냄
- 목적어와 동사 불일치: `비용을 총액으로 바꾼다`, `조건을 계산한다`
- 키워드 주체 불일치: `서비스센터 방문을 염두에 둔 광주 휴대폰 계약`, `기종을 받아야 하는 광주 휴대폰 계약`처럼 독자의 목적이나 행동을 계약 자체의 성질로 만듦
- SEO 문법 파손: `광주 휴대폰 성지 전에`처럼 정확 키워드 때문에 조사가 사라짐
- SEO 명사 겹침: `광주 휴대폰 계약 상담`, `광주 휴대폰 계약 조건`처럼 행동형 키워드 뒤에 추상 명사를 바로 붙임
- SEO 보충 문장: 키워드만 빼면 새 정보가 사라지는 문장, 부족한 횟수를 결론에 몰아 넣은 문장
- 현장 라벨 대체: 실제 장면 없이 `상담 현장`, `매장 운영`, `방문 후기`만 붙임
- 제작 흔적 노출: 사진 번호, 선택 지시, 빈 표 칸, 내부 JSON 키
- 종결어 획일화: 비슷한 길이의 모든 문장이 `~할 수 있습니다`로 끝남

오타, 어색한 조사, 가짜 일화로 사람을 흉내 내지 않는다. 자연스러움은 화자, 실제 상황, 구체적인 목적어, 정보의 진전에서 만든다.

## 독립 검수와 부분 재작성

검수자는 원고를 새로 쓰지 말고 항목별 점수와 문제가 있는 정확한 구간, 이유, `restore-master-role | replace-topic-content | fact-check | retitle` 중 하나의 조치만 반환한다. 제목·사실 팩·마스터 원문과 구조 맵·초안을 비교하고 작성자의 자기평가와 의심 구간은 전달하지 않는다. 다음을 의미 단위로 검사한다.

1. 제목의 약속과 본문 답이 같은가
2. 근거 없는 숫자·우월성·경험·보장이 있는가
3. 같은 뜻을 단어만 바꿔 반복하는가
4. 지시어의 대상이 앞에 나왔는가
5. 하나의 대상을 서로 다른 비유로 바꾸는가
6. 주어·목적어·동사가 실제 의미에 맞는가
7. 대표가 고객에게 소리 내어 말하기 어려운 문장인가
8. 내부 라벨, SEO 흔적, 사진 지시가 남았는가
9. 블록 수·문단 순서·후킹 수·소제목 수·증거와 CTA 위치가 마스터와 같은가
10. 마스터에 없는 3멘트·2차 후킹·마무리·표·증거 블록이 추가됐는가
11. 질문 호흡, 단호한 한 줄, 괄호 문단, 문장 길이 리듬이 마스터 말투와 같은가
12. 화자의 이름만 있고 입장·판단·말투가 본문에서 사라졌는가
13. 마무리가 실제 사진·표창·금액·개월·서류 항목 대신 `답변과 서류가 맞으면 결정` 같은 추상 공식으로 끝나는가

반복 문장은 마스터의 대응 문장 역할을 확인한다. 역할이 없는 추가 문장만 삭제하고, 마스터에 필요한 문장이면 같은 위치와 문장 수를 유지한 채 새 사실·원인·예외로 구체화한다. 전체 원고 재작성은 최대 한 번만 허용하고, 부분 재작성은 두 번 안에 끝낸다.

## 말투

- 기본 종결은 `~습니다`, `~인데요`, `~실 겁니다`, `~라고 생각합니다`를 문맥에 따라 섞는다. 종결어 할당량을 만들지 않는다.
- 독자의 예상 질문이나 반론은 짧은 따옴표 문장으로 사용할 수 있다. 질문 뒤에는 공감이나 직접 답을 붙인다.
- `꼭 저희가 아니라도`, `비교해 보셔도 좋습니다` 같은 저압 표현은 마스터에 있을 때만 같은 위치와 횟수로 새 제목에 맞게 치환한다.
- 이모지, 과도한 감탄사, 해시태그 장식, 이탤릭, 취소선을 쓰지 않는다.
- `사기`, `불법`, `폰팔이`, `호구`, `무조건`, `절대`는 제목과 글 유형이 경고·피해예방을 약속하면 자동 사용한다. 특정 개인·업체에 대한 범죄 단정이나 가격·효과 보장에는 쓰지 않고, 검색어·질문·일반 위험 패턴·독자의 안전 행동에 연결한다.
- 글자 수를 채우기 위한 연결문과 메타 요약을 만들지 않는다.

## 꾸미기·미디어·HTML

텍스트가 발행 게이트를 통과한 뒤 모든 글에 적용한다. HTML 생성은 선택사항이 아니다.

- 모든 글에서 [references/reference-decoration-profiles.md](references/reference-decoration-profiles.md)를 읽고 `decorationMasterReferenceId = masterReferenceId`를 먼저 확정한다. 선택한 마스터의 프로필이 없으면 원문 SmartEditor DOM을 분석해 프로필을 만든 뒤에만 HTML을 만든다.
- 실질 본문의 정렬, 한 의미 덩어리의 여백, 글자 크기 단계, 색, 배경 하이라이트, 표, 인용구, 사진, 캡션, 지도, 연락처 순서를 같은 마스터와 동일하게 유지한다. 모든 글에 중앙 정렬·청록색 박스를 자동 적용하지 않는다.
- 줄바꿈은 선택한 주 마스터의 실제 네이버 문단 단위를 그대로 따른다. 일반 본문은 375px 모바일 화면에서 **짧은 문장 2~3줄을 한 덩어리로 배치한 뒤 U+2060 간격 문단을 정확히 1개 넣는 리듬**을 기본 계약으로 삼는다. 다음 덩어리도 같은 `2~3줄 → 빈 줄 1칸` 리듬을 반복한다.
- 단순히 문장마다 `<p>`만 나누고 빈 줄 없이 4줄 이상 연속 배치한 결과는 실패다. 한 `<p>`가 모바일에서 두 줄로 감기면 그 두 줄도 덩어리의 줄 수에 포함한다. 따라서 긴 문장은 의미 경계에서 더 짧게 나누고, 각 덩어리가 실제 화면에서 2~3줄인지 확인한다.
- 마스터가 한 줄씩 별도 텍스트 컴포넌트로 작성되어 있으면 새 글도 같은 방식으로 짧은 `<p>`들을 연속 배치한다. `<br>`는 자동 줄바꿈 용도로 쓰지 않으며, 표·인용구·캡션·연락처·이미지 설명은 마스터에 등록된 줄바꿈을 유지한다.
- 미리보기에서는 실제 내용 요소의 `margin-top` 또는 `margin-bottom`으로 18~28px 여백을 둔다. 네이버 복사용 DOM에서는 CSS margin, 빈 `<p>`, `<br>`, `&nbsp;`, U+200B가 모두 제거될 수 있으므로 사용하지 않는다. 네이버에서 직접 확인된 방식인 U+2060 WORD JOINER 하나를 담은 중앙 정렬 `<p>`를 의미 덩어리 사이에 한 줄씩 두어 실제 빈 줄을 보존한다. 이 문자는 화면에는 보이지 않지만 문단은 유지된다.
- 강조는 위험, 근거, 행동의 핵심 어구에만 사용한다.
- 주장 가까이에 실제 근거 이미지나 실제 비교값이 있는 표를 둔다.
- 사진·GIF는 미디어 참고자료의 최신성·문맥·직접 확인 규칙을 모두 통과한 파일만 사용한다.
- 추천 결과가 `placeholder`인데 마스터에 해당 미디어 슬롯이 있으면 관련 없는 자료나 빈 블록을 출력하지 말고 필요한 사진·GIF 한 가지만 요청한다.
- 사진 번호, 파일 선택 지시, 캡션 초안은 발행 본문과 분리한다.
- 지도는 확인된 연락 블록 뒤에만 배치하고 현재 주소를 확인한다.

다음 빌드·복사 절차를 매 글마다 수행한다.

1. 선택한 마스터의 실제 정렬·크기·색·강조·밑줄·표·사진·빈 줄을 인라인 스타일이 포함된 `<article>` fragment에 재구성한다.
2. fragment와 제목·마스터 URL을 `scripts/build_naver_copy_page.py`에 전달해 현재 사용자의 바탕화면에 `청년통신_{slug}.html`을 만든다. 빌더가 반환한 충돌 회피 절대 경로를 최종 경로로 사용하고, 선택 마스터 이미지의 `src`와 `data-reference-source-url`이 같은 원본 URL인지 확인한다.
3. 저장된 파일을 브라우저에서 열어 `네이버용 HTML 복사` 버튼을 실제로 클릭한다. 복사 대상이 `<article>`만인지, `text/html`과 `text/plain`이 모두 생성되는지, U+2060 빈 줄과 원본 이미지 URL이 보존되는지 확인한다.
4. 580px 데스크톱과 375px 모바일에서 직접 확인한다. 일반 본문이 `2~3줄 → 빈 줄 1칸`으로 반복되는지, 빈 줄 없이 4줄 이상 이어지는 덩어리가 없는지, 마스터의 밑줄 역할·표 위치·사진 순서가 유지되는지 확인한 뒤에만 완성 파일로 반환한다.

- 네이버 내부 `se-*` 클래스나 원문 UUID를 복제하지 않는다.
- 본문의 중앙·기본 정렬 비율과 빈 줄 호흡은 마스터 프로필을 따른다.
- 단순 미리보기 파일이 아니라 `네이버용 HTML 복사` 버튼이 있는 복사 페이지로 제공한다. 버튼·안내·페이지 배경은 복사 대상 밖에 두고, 실제 `<article>`만 별도 복사 루트 안에 둔다.
- 복사 버튼은 가능하면 `ClipboardItem`으로 `text/html`과 `text/plain`을 함께 기록한다. 브라우저가 이를 막으면 복사 루트의 DOM 범위를 선택해 `execCommand('copy')`로 서식을 보존하고, 그것도 실패할 때만 일반 텍스트로 내린다.
- 복사되는 HTML은 외부 스타일시트에 의존하지 않고 문단·강조·표·연락처에 인라인 스타일을 사용한다. 버튼이나 스크립트, 미리보기용 회색 배경은 복사하지 않는다.
- 네이버용 복사 직전에 본문 DOM을 복제한다. `p[aria-hidden]` 미리보기 여백은 제거하지 말고 `aria-hidden`과 기존 스타일을 지운 뒤, U+2060 WORD JOINER 하나를 담은 중앙 정렬 빈 줄 문단으로 교체한다. 복사 결과에 `&nbsp;`, 텍스트가 `-`, `ㅡ`, `—`뿐인 문단, 내용 없는 `<p>`, `<p><br></p>`가 없는지 확인한다.
- 네이버용 HTML에서 선택한 마스터의 등록 밑줄을 `<u data-reference-underline-role="...">`로 유지한다. 프로필에 없는 임의 밑줄이나 문단 전체에 번지는 `text-decoration` CSS는 넣지 않는다. 경고형 `warning-seller-lines-01`은 후킹 3개, 위험 경고 1개, 판매자 약속 1개, 전화번호 1개, 연락 안내 2개로 총 8개 밑줄을 유지한다.
- 일반 본문과 article 전체에 회색 하이라이트를 공통 적용하지 않는다. 마스터에 실제로 등록된 강조 문장 슬롯의 배경만 유지하고, 복사 준비 단계에서 일반 텍스트가 그 배경을 상속하지 않도록 투명 배경을 명시한다.
- 네이버 SmartEditor는 붙여넣기 대상 문단에서 `B` 또는 `U`가 활성화되어 있으면 복사 HTML의 `font-weight:400`이나 `text-decoration:none`보다 편집기 상태를 우선하여 전체 글에 굵기·밑줄을 강제한다. 복사 페이지 상단과 복사 완료 메시지에 `네이버 본문에서 B·U가 켜져 있으면 먼저 끄기`를 명시한다. 재붙여넣기 전에는 기존 글을 지운 뒤에도 B·U 상태가 남아 있는지 반드시 확인한다.
- 신뢰 근거·연락처 표 제목은 청록색 배경 한 겹만 사용한다. 제목 셀 안쪽 `<span>`에 별도의 연한 파란색 배경이나 하이라이트를 중첩하지 않는다. 신뢰 근거가 표 역할을 할 때만 네이버 기본 표로 만들고 장식용 박스를 만들지 않는다.
- 마스터가 네이버 기본 인용구를 사용하면 `<blockquote>`와 짧은 출처 줄로 재구성한다. 장식용 배경 카드나 임의의 큰 제목 블록으로 바꾸지 않는다.
- 완성 파일은 실제 버튼 클릭과 클립보드 MIME 유형을 확인하고, 580px 데스크톱과 375px 모바일에서 모든 일반 본문 덩어리가 `2~3줄 → U+2060 빈 줄 1칸`으로 반복되는지 시각 검수한다. 빈 줄 없이 4줄 이상 이어지면 발행하지 않는다.
- 완성 파일은 `python3 scripts/validate_reference_decoration.py HTML파일 --profile 마스터ID`도 통과해야 한다.
- 강조는 인라인 스타일과 `<strong>`을 사용한다.
- 표는 모바일에서 읽히는 1~2열 구조로 제한한다.
- 실제 자료는 자산 ID가 있는 `<figure data-cheongnyeon-media="A00000">`에 넣는다.
- 실제 자료가 없으면 빈 `<figure>`나 보이는 placeholder를 만들지 않는다.
- 캡션과 `alt`는 파일을 직접 확인한 뒤 사실형으로 작성한다.

## SEO와 제목 추천

- 메인키워드는 제목 앞부분에 문법적으로 자연스럽게 한 번 사용한다.
- 본문에는 정확한 메인키워드를 정확히 5회 사용한다. 제목 1회와 본문 5회를 따로 계산한다.
- 표, 사진 설명, 연락처, 지도, 출처, CTA는 본문 횟수에 포함하지 않는다.
- 선택한 신뢰 근거 오버레이도 본문 횟수에서 제외한다. 메인키워드가 오버레이의 매장 표기와 같아도 일반 본문에서 별도로 정확히 5회 사용한다.
- 다섯 번의 등장은 독자 상황, 문제 원인, 놓치기 쉬운 장면, 확인 방법, 해결책, 화자 판단, 매장 연결, 결론 중 서로 다른 역할을 맡아야 한다. 한 문단에는 한 번만 쓰고 도입·중간·후반에 분산한다.
- 먼저 필요한 내용을 쓰고 그 문장의 자연스러운 명사구에 정확 키워드를 결합한다. 키워드 앞에는 구체적인 상황이나 수식어를 두고, 뒤에는 조사·시간 관계·서술어를 문법에 맞게 잇는다.
- 부족한 횟수를 채우려고 새 문장, 새 문단, 요약 블록을 추가하지 않는다. 이미 필요한 문단 전체를 다시 써도 5개의 서로 다른 역할을 만들 수 없으면 발행하지 않고 제목·자료·구성을 다시 검토한다.
- 같은 키워드로 시작하는 문단을 연속해서 만들지 않는다. `실제 [키워드] 상담에서도`, `[키워드] 조건은`, `[키워드] 견적·선택·비교 기준은` 같은 명사 겹침 문장을 쓰지 않는다.
- 세부 배치와 검수 규칙은 [references/keyword-integration.md](references/keyword-integration.md)를 따른다.
- 제목 추천은 근거가 있는 후보와 패턴 참고용 후보를 구분한다. 최종 발행 제목에는 검증된 사실만 사용한다.
- 메인키워드를 제목 안에서 반복하거나 지역명을 중복하지 않는다.
- 제목 길이는 공백 제외 22~40자를 권장한다. 40자를 넘으면 먼저 압축하되, 레퍼런스의 구체 약속을 지우거나 문장을 어색하게 자르지 않는다. 50자를 넘으면 발행하지 않는다.

## 발행 게이트

다음 중 하나라도 남으면 발행본으로 출력하지 않고 안전하게 고친 뒤 다시 검사한다.

- 제목과 본문의 답이 다름
- `scripts/validate_title.py`가 실패했거나 선택한 `ideaReferenceId`·`titlePatternId`가 기록되지 않음
- 자동모드 제목의 주인공이 구매자의 돈·계약·기기·요금·손해가 아니라 문의량·운영·확장 같은 매장 성과임
- 외부 아이디어 출처의 업체명·인물·지역·판매량·순위·가격·보장·후기·경력·전화번호가 제목 또는 본문에 유입됨
- 확인되지 않은 숫자·우월성·보장·경력·경험
- 같은 의미의 결론이나 행동 반복
- 내부 기획어, `CHECK` 라벨, 보이는 placeholder
- 문법을 깨뜨린 키워드 삽입 또는 키워드 군집
- 본문 정확 키워드가 5회가 아니거나, 다섯 문장이 같은 역할·같은 문장 틀을 반복함
- 본문과 같은 내용을 옮긴 표·마무리
- 마스터와 다른 블록 수·후킹 문장 수·소제목 수·정보 공개 순서·CTA 위치
- 마스터에 없는 3멘트·2차 후킹·마무리·증거 블록을 자동으로 추가함
- 실제 근거 없는 고객 발화나 대표 경험
- 목적어·동사 불일치 또는 대상을 잃은 지시어
- `답변과 서류가 맞을 때`, `결정하셔도 늦지 않습니다` 또는 같은 의미의 추상 명사 대조형 마무리가 남음
- 제목과 다른 글 유형을 선택했거나 중립 주제에 강한 표현을 억지로 넣음
- 마스터의 신뢰 근거 블록이 누락됐거나 현재 사실이 아닌 과거 수치·시점 표현을 사용함
- HTML의 `decorationMasterReferenceId`가 글쓰기 `masterReferenceId`와 다르거나 다른 글의 색·표·인용구를 섞음
- 마스터 꾸미기 프로필의 정렬·강조 역할·색·표 행 수·인용구 수를 따르지 않거나 장식 검문이 실패함
- 프로필에 등록된 밑줄 문장 역할·위치·횟수가 빠지거나 임의 밑줄이 추가됨
- `반박분석 3멘트`를 선택했지만 세 멘트가 같은 뜻이거나 본문에서 하나 이상 답하지 않음
- 소비자 발화형 첫 후킹을 문의량·판매량·운영·박리다매·매장 확장 같은 브랜드 관심사로 치환함
- 2차 후킹이 첫 후킹의 의심을 반복하거나 본론에서 회수하지 않는 막연한 이익을 약속함
- 독자의 절약액·결과를 현재 근거 없이 보장하거나 업계 긴장 문장으로 특정 경쟁사를 단정함
- 대표 전화 `010-8489-4440` 또는 네이버 예약 고정 마감이 빠짐
- 제목과 실제 본문 합계가 공백 제외 1,400자 미만 또는 1,800자 초과
- 빌더가 반환한 현재 사용자 바탕화면의 절대 경로에 비어 있지 않은 HTML 파일이 없거나, 선택 마스터 이미지가 로컬 경로에 의존함
- HTML 파일에 `네이버용 HTML 복사`, `ClipboardItem`, `<article>` 복사 루트가 없음
- article fragment와 최종 HTML 중 하나라도 `scripts/validate_article.py` 또는 `scripts/validate_reference_decoration.py`를 통과하지 못함
- 복사 버튼·`text/html`/`text/plain` MIME·U+2060 빈 줄·원본 미디어 URL·모바일 줄바꿈을 실제로 확인하지 않음

파일 원고는 다음을 실행한다.

`python3 scripts/validate_title.py --title "제목" --keyword "메인키워드" --idea-reference-id "선택 ID" --pattern-id "선택 패턴"`

`python3 scripts/validate_article.py 원고파일 --keyword "메인키워드" --evidence references/brand_facts.md --evidence references/temporary_information.md`

사람용 결과와 `--json` 결과를 모두 확인한다. 오류는 반드시 부분 수정하고 경고도 원문 구간을 확인한다. 두 번의 부분 수정으로 통과하지 못하거나 새로운 사실이 필요하면 원고 출력을 중단하고 자료 요청으로 전환한다.

## 응답

자료가 충분하고 검수 결과가 `pass`일 때는 완성 제목과 블로그 본문을 간단히 보여 주고, 바탕화면에 저장한 HTML 파일의 절대 경로를 클릭 가능한 링크로 반환한다. 모든 완성 글 응답의 마지막에는 역할이 다른 아래 세 링크를 반드시 함께 출력한다.

```text
HTML 저장 완료: [청년통신_제목.html](빌더가 반환한 현재 사용자 바탕화면의 절대 경로)
주제·제목 참고 글: [선택한 외부 아이디어 글 제목](선택한 외부 아이디어 글의 실제 URL)
말투·구조·꾸미기 참고 글: [선택한 청년통신 주 마스터 표시명](선택한 cjdsus4444 대표글의 실제 URL)
```

`HTML 저장 완료`에는 빌더가 실제로 반환한 최종 파일 경로를 사용한다. `주제·제목 참고 글`에는 아이디어 프로필의 실제 원문 링크를, `말투·구조·꾸미기 참고 글`에는 이번 글에 사용한 `cjdsus4444` 주 마스터 한 편의 실제 링크를 넣는다. 두 링크를 하나의 `참고 레퍼런스`로 합치거나 역할을 바꾸지 않으며, 링크를 생략하고 내부 ID만 출력하지 않는다. 본문을 네이버에 붙여넣을 때는 macOS에서 `네이버 본문에서 B·U 끄기 → HTML 파일의 네이버용 HTML 복사 클릭 → 네이버 본문에 ⌘V`, Windows에서 같은 순서로 `Ctrl+V`를 안내한다. 계획, 사실 ID, 검수 결과, 키워드 횟수, 글자 수, 사진 번호, 내부 작업 지시는 출력하지 않으며, 사용자가 묻지 않으면 레퍼런스 내부 ID도 노출하지 않는다.

자료가 부족하거나 두 번의 부분 수정 뒤에도 통과하지 못하면 원고를 섞지 않고 다음 형식만 출력한다.

```text
[추가로 필요한 자료]

1. ...
2. ...
```
